# 완성 코드 읽기와 작은 변경 과제

## 사용자 흐름과 범위

데모 시작 → 서버 로그인·합성 persona 배정 → 기간 선택 → 거래·요약 → 같은 달의 또래 비교. 모든 대표 화면의 금액은 서버 원장에서 나옵니다. 실제 은행 연동·소비 추천·이미지 생성은 이 흐름에 포함되지 않습니다. 기존 팀 결과와 이 브랜치의 개인 보강을 README에서 구분합니다.

## 한 요청을 읽는 순서

1. `api/MeController.overview`: 토큰에서 `CurrentPersona`로 본인을 확인하고 기간·기준일을 받습니다.
2. `metrics/PeriodType`: 일간·일요일 시작 주간·기준일까지 월간을 정합니다.
3. `metrics/OverviewService`: 적재 범위를 검사하고 원장 SQL로 소비·저축·투자·소득을 나눕니다. `NO_DATA`와 0원을 구분합니다.
4. `ledger/TransactionService`: 같은 기간의 원장을 날짜·ID 순서로 페이지 조회합니다.
5. `metrics/PeerCompareService`: 월 전체가 준비된 동일 소득대의 평균을 구합니다. 본인 포함, 무거래 0원입니다.
6. `metrics/MonthlyRollup`: 원장으로 집계를 재생성합니다. DELETE와 INSERT를 같은 트랜잭션으로 처리해 마지막 거래가 삭제된 집계도 제거합니다.
7. 앱 `src/features/spending/SpendingPage.tsx`: 독립적인 세 조회를 함께 시작하고, 실패·자료 없음·정상 결과를 구분합니다.

## 데이터 모델과 선택

`finmate_user → persona → ledger_entry`, `persona → persona_month`입니다. 계정과 비교용 합성 인구를 구분합니다. 일반 인증은 JPA, 대량 적재와 집계는 SQL을 사용합니다. 원장이 기준이며 집계는 재생성 가능한 파생 자료입니다.

프로필·CSV 적재가 한 트랜잭션이고 모든 자료를 가진 bundle이라는 전제여서 `data_from/data_to`를 적재 완료 범위로 사용했습니다. 중간에 일부 달만 적재하는 수집기로 바꾸면 이 전제가 깨집니다. 별도 수집 완료 표가 필요하며, 누락을 0원으로 처리해서는 안 됩니다.

`rebuildAll`의 전체 재생성은 현재 읽기 중심 배치 데모에 맞춘 선택입니다. 원장 쓰기·재집계의 동시 실행 규칙은 아직 API로 제공하지 않습니다. 상대가 바꾼 자료를 조용히 덮는 온라인 갱신 체계까지 완성했다는 의미가 아닙니다.

## 실패 조건을 확인하는 테스트

`PeerAccuracyIntegrationTest`: 100원 지출자 + 무거래자 = 평균 50원, 미적재 월, 월 일부만 적재된 사람, 마지막 거래 삭제, 대안 SQL 결과 일치.

`MeFlowIntegrationTest`: 기간 변경, 자료 없는 기간, 로그인·본인 확인, 거래 목록. 일반 통합 테스트는 `demo/bundles`를 사용하며 개인 컴퓨터 경로가 필요 없습니다.

앱 `e2e/spending.spec.ts`: 실제 API로 시작·기간 변경·비교를 확인하고, 별도 실패 시나리오에서만 HTTP 503을 주입합니다. API를 가짜 성공 응답으로 대체하지 않습니다.

## 강의와 연결해 공부하기

아래는 강의 원문 요약이 아니라 이 코드에 연결한 학습 순서입니다. 전체 강의를 이번 작업에서 시청한 것은 아닙니다.

- 김영한 Spring MVC: Controller의 요청 파라미터·DTO·오류 응답을 읽습니다.
- 김영한 Spring DB 1·2: `@Transactional`, JDBC, 원장과 집계 변경의 커밋 경계를 확인합니다.
- 김영한 JPA·Spring Data JPA: 인증 엔티티와 조회 SQL을 비교하고 왜 집계에서 엔티티 전체를 로딩하지 않는지 설명합니다.
- 딩코딩코 2·3주차: 같은 답을 먼저 검증한 다음 실행 계획·인덱스 크기·원표본을 읽습니다.
- 생각등대 가이드: 위 조건과 선택·관측·한계를 사례 문장으로 정리합니다. 실험을 운영 경험으로 바꾸지 않습니다.

## 직접 해볼 변경 과제

**평균에서 본인을 제외한다면?** 먼저 두 사람 100원·0원인 예에서 각자 받아야 할 값과 비교 대상이 0명일 때 응답을 적습니다. 테스트를 실패시킨 뒤 `peerCount`, `peerAvgSpend`, percentile의 분모와 화면 설명을 함께 수정해 보세요. 현재 코드의 소득대·적재 기간 기준을 유지해야 합니다.

그다음 한 사람의 마지막 거래를 삭제하고 재집계 전후 응답을 비교해, 원장과 집계가 달라질 수 있는 시간을 설명해 보세요.
