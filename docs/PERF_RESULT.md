# 동일한 평균 정의의 조회 대안 비교

2026-10-02 로컬 관측입니다. 운영 부하·HTTP 응답시간·사용자 통계가 아닙니다. 기존 `32.5ms → 0.72ms / 45배`는 정렬하지 않은 백분위와 서로 다른 모집단 정의가 발견되어 대표 주장으로 사용하지 않습니다. [과거 기록](archive/PERF_RESULT-2026-08-07.md)은 보존했습니다.

## 조건

Java 21.0.8, PostgreSQL 16.15, macOS aarch64, Testcontainers. 결정적 SQL 시드로 완전히 적재된 사람 2,000명, 이 중 지출자 1,800명, 6개월 × 월 40거래 = 432,000행을 만들었습니다. 2026년 7월을 소득대 4개로 비교합니다. 자료가 있는 무거래자 200명도 0원으로 포함합니다.

각 대안 워밍업 5회, 측정 40회, 실패 0/160. 모든 응답의 인원수·원 단위 반올림 평균이 동일한지 검사했습니다. 정렬한 사본에서 nearest-rank `ceil(p × n) - 1`을 사용합니다. 원본 배열은 측정 순서대로 보존합니다.

## 관측

대안 비교이며 수정 전후 측정이 아닙니다. 시간은 **JDBC 호출부터 결과 수신까지**입니다. 네트워크 왕복·결과 변환이 포함되므로 SQL 서버 내부 실행시간과 같지 않습니다. 각 [실행 계획](evidence/2026-10-02/peer-comparison/)의 `Execution Time`은 별도 단일 관측입니다.

| 대안 | p50 ms | p95 ms | max ms |
|---|---:|---:|---:|
| 원장 직접 집계·DISTINCT | 68.343416 | 87.190875 | 128.970917 |
| 사람별 집계 후 그룹 평균 | 37.003833 | 46.172291 | 62.067167 |
| 같은 재작성 쿼리 + 커버링 인덱스 | 9.817958 | 10.007667 | 10.480875 |
| 사람×월 사전 집계 | 3.531750 | 4.704375 | 4.977708 |

사전 집계 전체 재생성은 351.305ms, 집계 테이블·인덱스 합계 1,671,168 bytes, 비교용 커버링 인덱스 25,460,736 bytes였습니다. 갱신 비용 역시 이번 로컬 실행의 단일 관측입니다.

## 선택과 한계

데모는 배치로 완전히 적재한 읽기 중심 자료이므로 기존 월 집계를 유지합니다. 원장 변경 뒤 재집계를 완료하기 전에는 최신이 아닙니다. 실시간 거래 입력 API를 추가한다면 원장 변경과 해당 사람의 집계 갱신을 같은 업무 트랜잭션에 넣거나, 지연 허용 시간을 별도로 정의해야 합니다. 이번에는 실시간 수집·다중 집계 작업자·운영 캐시를 추가하지 않았습니다.

첫 세 대안은 반복마다 교대로 호출했고, 인덱스 대안은 인덱스 생성·VACUUM ANALYZE 후 따로 측정했습니다. 모두 warm cache, 단일 클라이언트이며 독립 실행 반복이나 통계적 신뢰구간은 없습니다. 인덱스 단계 순서와 로컬 자원 경합이 결과에 영향을 줄 수 있습니다. 실제 HTTP 부하는 이번에 재실행하지 않았습니다.
