# QA 및 인수 계획

## 1. 품질 목표

MVP는 추천 모험가의 루틴을 내 데이터에 맞는 목표로 안전하게 바꾸고, 검증된 실제 변화만 레이드에 반영해야 한다. 품질 우선순위는 다음과 같다.

1. 개인정보 공개·철회·삭제와 투자 게임화 안전
2. 금융 계산, 목표 생명주기, 진행률의 정확성과 재현성
3. AI 경계, 구조화 출력 검증과 결정론적 폴백
4. 핵심 퍼널의 완결성, 접근성, 성능과 관측 가능성

친구·팔로잉과 메이트 찾기는 Phase 2이며 MVP 빌드, 라우트, 이벤트, 테스트 데이터에 활성 기능으로 포함하지 않는다. 경제 보상, 금융상품·종목 추천, 투자금·수익률 목표는 인수 실패 항목이다.

3~4주 릴리스는 **계약 호환 어댑터와 합성 데이터만 사용하는 MVP 프로토타입**이다. 실제 마이데이터 수집·운영 자격증명·실제 고객 금융정보, 동의한 운영 표본과 100명·4주 파일럿 결과는 MVP 인수에 요구하지 않는다. 이 항목들은 실제 연동 준비가 끝난 뒤 별도 승인하는 post-MVP 검증 제안이다.

## 2. 테스트 환경과 데이터

| 환경 | 목적 | 데이터 |
| --- | --- | --- |
| 로컬 | 단위·공식·스키마 빠른 검증 | 고정 시계와 합성 거래 |
| CI | 전체 자동 회귀, 계약, 정적 안전 검사 | 버전 고정 골든 YAML과 가짜 AI·계약 호환 금융데이터 어댑터 |
| 스테이징 | 통합·E2E·접근성·성능·보안 | 계약 호환 어댑터와 버전 고정 합성 사용자 팩 |
| MVP 데모 | 릴리스 후보 수직 여정과 운영 절차 확인 | 스테이징과 같은 합성 시나리오만 사용, 운영 사용자·운영 자격증명 없음 |

테스트 데이터는 실제 고객 금융정보를 복제하지 않는다. 합성 데이터 팩은 정규소득 3개월, 불규칙소득 6개월, 내부이체, 환불, 대출 실행과 원금 상환, 만기 재예치, 중복 거래, 오래된 데이터, 분류 충돌을 포함한다. 모든 테스트는 `Asia/Seoul` 기준일과 UTC 저장 시각을 명시하고 외부 시계에 의존하지 않는다.

## 3. 자동화 계층

### 단위 테스트

- 거래 분류, 원금 상환을 정확히 한 번 포함한 필수지출 중앙값, 여윳돈, 반올림, `clamp`, 데이터 상태, 진행률과 단계 경계를 함수 단위로 검증한다.
- 동의 상태 전이, 후보 만료, 목표 생명주기, 일시정지 중 계산 차단, 멱등성 키를 검증한다.
- 이벤트 생성기가 허용 속성만 만들고 PII 금지 필드를 거부하는지 검증한다.
- AI 출력 파서, JSON 스키마, 후보 ID 허용 목록, 수치 불변, 금지 문구 검사를 각각 검증한다.
- AI `reasonCodes`가 선택 카드·후보의 공급 근거 부분집합인지, 요약의 모든 주장이 공급된 승인 문장으로 입증되는지 검증하고 불일치 시 전체 출력 폐기와 폴백을 확인한다.
- `verified_action_recorded` 재전송 중복 제거, `effective_at` 주차 변환, `app_foregrounded` 동의 게이트와 D7·D28 날짜 경계를 검증한다.
- 핵심 도메인 코드의 문장·분기 커버리지는 90% 이상, 전체 변경 코드 80% 이상이어야 한다. 커버리지 수치만으로 경계값 테스트를 대체하지 않는다.

### 공식·속성 테스트

다음 불변조건을 예제 기반과 생성 기반 테스트로 확인한다.

```text
월 필수지출 = sum(DEBIT ESSENTIAL_EXPENSE) + sum(DEBIT LOAN_PRINCIPAL)
여윳돈 = 기준 월소득 - median(완료월별 월 필수지출)
alphaBps = LIGHT 2500, STANDARD 5000, CHALLENGE 7500
증가형 분자 = 기준값 × 10000 + (참고값 - 기준값) × alphaBps
감소형 분자 = 기준값 × 10000 - (기준값 - 참고값) × alphaBps
```

- `LOAN_PRINCIPAL` 원금 상환은 수용력 필수지출에 canonical 거래당 정확히 한 번 포함하고 재량지출·소비절감 목표에서는 제외한다. 대출 실행금은 소득·필수지출·성과에서 제외한다. 원금 누락과 이중 집계 fixture를 모두 실패시킨다.
- 참고값이 개선 방향이 아니거나 반올림 뒤 기준값과 같으면 정량 후보가 없다.
- 여윳돈이 0 이하이거나 데이터가 부족하면 소비율·저축률·투자율 후보가 없다.
- 내부이체·환불·대출 실행·재예치·중복 거래는 성과에 중복 포함되지 않는다.
- 난이도 변화 폭은 `LIGHT ≤ STANDARD ≤ CHALLENGE`이며 모두 템플릿 안전 범위 안이다.
- 진행률은 `0..10000 bp` 범위를 벗어나지 않고, 최고 진행률은 감소하지 않는다.
- 퀘스트 완료만으로 금융 스탯·목표 진행률·레이드 단계가 오르지 않는다.

### 계약 테스트

- `RecommendedAdventurerCard`, `GoalCandidate`, `ActiveGoal`, 홈 확장 응답의 필수 필드·열거형·추가 필드 정책을 검증한다.
- 카드 응답에 `sourceProfileKey`, 정확 금액, 거래 원문, 상품·종목, 수익률이 없음을 음성 테스트로 검증한다.
- 후보 확정 API는 만료, 데이터 변경, 동의 버전, 활성 목표 충돌, 멱등 재시도를 검증한다.
- 공개 `cancelQuest` 계약은 `POST /quests/{questId}/cancel`, `If-Match`, 멱등성 키, 취소 사유, `CANCELLED` 응답을 검증한다. 취소 재전송은 같은 응답을 재생하고 XP·금융 스탯·목표 진행률을 바꾸지 않아야 한다.
- 공개 계산 API는 endpoint별 OpenAPI domain payload를 그대로 반환하고 공통 최상위 `result` wrapper를 추가하지 않는다. 각 스키마가 요구한 `dataFreshness`와 `calculationVersion` 또는 계산 메타데이터의 위치를 검증한다.
- Prism 목 명세 생성기는 원본 OpenAPI의 모든 로컬 `externalValue`를 정확한 JSON `value`로 바꾸고 외부 참조를 0개로 만들어야 한다. 생성 명세의 공개 철회 200, stale opt-in 412, 퀘스트 취소 200은 각각 원본 fixture와 일치해야 한다.
- AI 입력·출력 스키마와 분석 이벤트 스키마는 생산자·소비자 양쪽에서 호환성을 검증한다.
- MVP 라우트 목록에 친구·팔로잉·사용자 검색·메시지 API가 없음을 검증한다.

### 통합 테스트

- 계약 호환 어댑터의 합성 데이터 수집 → 분류 → 기준선 → 카드 적격성 → 후보 계산 → 목표 확정 → 진행률 스냅샷 → 홈 레이드 갱신을 검증한다. 실제 마이데이터 제공자 연결은 이 통합 인수 범위가 아니다.
- 각 `SyncJob`/`SyncRun`이 `SUCCEEDED | PARTIAL_FAILED | FAILED | BLOCKED`에서 종결된 뒤 상태를 유지하는지 검증한다. 재시도는 새 `syncRunId`와 `retryOfSyncRunId`로 시작해야 하며 `IDLE`은 scheduler/connection readiness에만 존재하고 persisted job status에는 없어야 한다.
- 공개 철회 → 조회 차단 → 인덱스·캐시·파생 추천 제거 → 기존 확정 목표의 원본 연결 제거를 검증한다.
- 동의 부여·철회 경합은 같은 `consentAggregateId`에서 철회 명령의 `expectedVersion`을 먼저 적용하고 지연 부여 명령을 `412 / PRECONDITION_FAILED`로 거절하는 순서를 검증한다. 계정 삭제, AI 감사 로그 삭제·법정 보존 분리, 백업 복원 후 삭제 원장 재적용도 함께 검증한다.
- AI 정상, 타임아웃, 공급자 5xx, 잘못된 JSON, 허용되지 않은 ID, 수치 변조, 근거 불일치에서 동일한 폴백을 검증한다.
- 이벤트 큐 재전송과 순서 역전에서도 멱등 상태와 KPI 이벤트 중복 제거가 유지되고, 반복 검증 행동의 `effective_at` 및 포그라운드 세션으로 4주·D7·D28 변환이 재현되는지 검증한다.

### E2E 테스트

필수 사용자 여정은 데스크톱 웹 1440×900, 모바일 웹 390×844, 지원하는 iOS·Android 대표 기기에서 실행한다.

1. 온보딩과 합성 어댑터용 동의 상태 설정 후 목표 없는 홈 진입
2. 비교 탐색에서 익명 카드 공개 범위 확인
3. 성장 방식 보기, 루틴 선택, 세 후보 비교
4. 사용자 확정 후 홈 레이드와 연결 퀘스트 확인
5. 반영 대기·오래됨·확인 필요 상태 확인
6. 목표 일시정지·재개·취소, 공개 퀘스트 취소와 기록 보존 확인
7. 익명 카드 공개 동의 거부·부여·철회와 재노출 차단 확인
8. AI 장애에서 결정론적 fallback 추천·요약·주의 문구를 확인하고 후보 선택·거절·취소 완료
9. 레이드 연출 축소·끄기 후 같은 금융 기능 이용

각 여정은 화면 검증과 함께 서버 상태, 감사 로그, 핵심 이벤트를 확인한다. 입력은 합성 픽스처로 고정하며 실제 마이데이터 계정 연결이나 운영 사용자 동의 기록을 요구하지 않는다.

## 4. 비기능 인수 기준

### 접근성

- WCAG 2.2 AA 수준을 목표로 자동 검사와 키보드·스크린리더 수동 검사를 모두 통과한다.
- 모든 기능을 키보드로 사용할 수 있고 초점 순서와 표시가 논리적이어야 한다.
- 카드, 후보 선택, 동의, 데이터 상태, 레이드 단계는 색상만으로 구분하지 않는다.
- 일반 텍스트 명도 대비 4.5:1, 큰 텍스트 3:1, UI 경계·초점 3:1 이상을 만족한다.
- 200% 확대와 320 CSS px 너비에서 정보·기능 손실, 가로 스크롤, 텍스트 겹침이 없어야 한다.
- 연출 끄기와 운영체제 `prefers-reduced-motion`을 존중하며 자동 반복 전투 연출을 정지할 수 있어야 한다.
- 동적 데이터 상태와 목표 확정 결과는 적절한 라이브 영역으로 알리되 반복 안내하지 않는다.
- 접근성 자동화 심각·중대 위반 0건, 수동 핵심 여정 차단 이슈 0건이 인수 기준이다.

### 성능·복원력

| 항목 | 조건 | 인수 기준 |
| --- | --- | --- |
| 카드 목록 API | 30 RPS, 15분, 캐시 정상 | P95 400ms 이하, 오류율 0.5% 이하 |
| 후보 생성 API | 15 RPS, 15분, 계산·저장 포함 | P95 800ms 이하, 오류율 0.5% 이하 |
| 목표 확정 API | 10 RPS, 멱등 재시도 10% 포함 | P95 700ms 이하, 중복 목표 0건 |
| 홈 API | 30 RPS, 활성 목표 포함 | P95 500ms 이하, 오류율 0.5% 이하 |
| AI 설명 | 게이트웨이부터 검증 종료 | P95 2.5초 이하, 3초 내 폴백 노출 |
| 웹 핵심 화면 | 모바일 중간급, 제한 네트워크 | LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하 |
| 철회 처리 | 캐시·큐 장애 주입 포함 | 조회 차단 5분 이내, 완전 제거 24시간 이내 |

AI, 분석, 알림 장애가 목표 조회·확정·취소를 막지 않아야 한다. MVP에서는 합성 어댑터 지연을 주입해 이전 검증값과 기준일을 표시하고 실패나 보스 회복으로 표현하지 않는지 확인한다.

### 보안·개인정보

- 인증·인가, 객체 수준 권한, 입력 검증, 속도 제한, 비밀정보 관리, 암호화, 감사 로그를 위협 모델 기준으로 검사한다.
- 카드·목표 ID를 순회해 타인의 P1/P2 데이터를 얻을 수 없어야 한다.
- 로그·오류·분석 이벤트·AI 입력에 정확 금융값, 거래 원문, 인증 토큰, 원본 카드 사용자 키가 없어야 한다.
- 동의 경합·재전송으로 `WITHDRAWN`이 `GRANTED`로 되돌아가지 않아야 한다.
- 프롬프트 주입, JSON 탈출, 긴 입력, 유니코드 혼동, 허용되지 않은 후보 ID는 모두 차단되고 폴백해야 한다.
- 활성 AI 동의에서도 `OPERATIONAL`은 생성 후 최대 90일, `INCIDENT_EVIDENCE`는 최대 180일만 보존한다. 계정 삭제와 AI 동의 철회 시 두 비법정 분류의 내용·가명·사고·사용자 연결을 7일 안에 삭제하거나 비가역 분리하며, 열린 사고만으로 삭제를 면제하지 않는다.
- `LEGAL_REQUIRED`는 철회·삭제 요청 전에 `legalBasisCitation`, `retentionExpiresAt`, `recordScope`, `approvedBy`, `legalCaseId`, 법무 승인 시각이 모두 고정된 레코드만 허용한다. 일반 서비스 운영 데이터는 계정 삭제 후 7일 안에 삭제되어야 한다.
- 백업은 생성 후 최대 30일 안에 만료한다. 복원 후 삭제 tombstone 원장을 재적용하기 전에는 서비스가 열리지 않고 삭제 대상과 가명 매핑 재등장 건수가 0이어야 한다.
- 의존성의 알려진 치명·높음 취약점 0건, 동적 스캔의 치명·높음 이슈 0건이어야 한다. 예외는 보안 책임자와 제품 책임자의 기한 있는 서면 승인 없이는 허용하지 않는다.

## 5. 골든 테스트 운영

`golden-test-cases.yaml`은 계산과 정책의 승인 예시다. 테스트 러너는 각 케이스의 `given`, `when`, `expect`를 어댑터로 도메인 서비스에 전달하고 다음을 출력한다.

- 케이스 ID와 구현 요구사항 연결
- 실제·기대 JSON 구조 차이
- 사용한 계산·템플릿·정책 버전
- 실패 시 고정 시계, 입력 데이터와 재현 명령

골든 수치 계약은 단위 변환을 허용하지 않는다.

- 모든 비율 입력·기대값·임계값·난이도 계수는 `_bps`로 끝나는 명시적 field의 YAML integer다. `100 bp = 1%`, `10000 bp = 100%`지만 러너는 값을 100배 하거나 100으로 나누지 않고 정수 그대로 전달·비교한다.
- YAML float, `_percent` field, `0.25` 같은 fraction 계수와 기계 입력의 `"14%"` 문자열을 발견하면 fixture parse 단계에서 실패한다. 표시 문구를 검증하는 별도 문자열도 계산 입력으로 재해석하지 않는다.
- `raw_target_value_bps = 1025`처럼 반올림 전 유리수 결과가 정수 bp로 정확히 표현되는 사례도 정수로 기록한다. 더 높은 정밀도가 필요하면 분자·분모 integer field를 문서화해 추가하며 암묵적 소수 변환을 만들지 않는다.
- 전체 계산 봉투는 내부 계산·골든·합성 시나리오·영속화 계약에서만 사용한다. 공개 HTTP fixture는 OpenAPI domain payload를 검증하고 공통 `result` wrapper를 기대하지 않는다.

기존 케이스 ID는 외부 문서 참조 호환성을 위해 변경하지 않는다. 총 케이스 수는 이 문서에 고정하지 않고 `golden-test-cases.yaml`을 정본으로 계산한다. 요구사항 추적표와 결정 로그는 별칭을 만들지 않고 YAML의 실제 `id`를 직접 참조하며, CI는 참조 ID 누락과 중복 ID를 실패로 처리한다.

추적성 전용 그룹은 온보딩·원금 포함 기준선, 동기화 terminal 실행과 새 실행 재시도, 목표 생명주기, 레이드 경계·최고 기록·대기, 퀘스트 증거와 공개 취소, 동물 리포트, 30일·일일 기록, 공개 동의 경합, AI 보존·계정 삭제·백업 tombstone, MVP 금지 표면, mock·합성 어댑터 E2E, 내부 계산 봉투와 OpenAPI 예시 계약을 포함한다. 각 케이스는 `given`, `when.action`, `expect`를 가져야 하며 단순 문서 존재 여부 대신 상태와 계산 결과를 구체적으로 검증한다.

골든 값 변경은 단순 스냅샷 갱신으로 처리하지 않는다. 제품, 백엔드, QA 중 2명 이상이 계산 근거와 사용자 영향을 리뷰하고, 개인정보·AI·투자 안전 케이스는 해당 책임자가 추가 승인한다. 버전 변경 중에는 이전·새 계산을 병렬 실행해 기존 활성 목표가 고정 버전으로 끝나는지 확인한다.

## 6. 탐색·사용성 학습

합성 프로필만 표시하는 프로토타입으로 금융 초보 청년 5~10명이 익명 카드와 공개 범위, 상대 금액이 아닌 루틴을 가져오는 원칙, 세 후보 차이, 데이터 반영 대기, 투자 판단 영역의 의미를 자신의 말로 설명하게 할 수 있다.

과제 완료율 80% 이상, 루틴 가공 원칙 이해 80% 이상, 투자 판단이 투자금·수익률 경쟁이 아니라는 이해 90% 이상, 목표 적절성 중앙값 4/5 이상은 디자인 학습 목표다. 이 소규모 세션은 MVP 인수 증거나 제품 KPI 달성 증거가 아니다. 압박·수치심 또는 개인정보 불안이 확인되면 화면별 근거를 기록하고 합성 시나리오 회귀 테스트를 추가한다.

## 7. 결함 심각도와 출시 게이트

| 등급 | 예시 | 처리 |
| --- | --- | --- |
| S1 | 개인정보 노출, 철회 후 24시간 초과 노출, 잘못된 AI 수치·ID 노출, 투자 유도 보상, 데이터 손상 | 즉시 배포 중지·롤백 또는 기능 차단, 사고 대응 |
| S2 | 목표 계산 오류, 중복 활성 목표, 핵심 여정 차단, 접근성 핵심 차단 | 릴리스 전 수정 필수 |
| S3 | 우회 가능한 기능 오류, 일부 이벤트 누락, 비핵심 접근성 문제 | 책임자·수정일 지정 후 제한 승인 가능 |
| S4 | 문구·시각 정렬 등 영향이 작은 문제 | 백로그 등록 가능 |

릴리스 후보는 다음을 모두 만족해야 한다.

- 계약 호환 어댑터와 합성 데이터만 사용하며 실제 마이데이터 자격증명·운영 고객 표본이 없음
- 단위·공식·계약·통합·E2E·골든 테스트 전수 통과
- S1·S2 미해결 0건, S3 예외에 책임자와 수정일 존재
- 접근성·성능·보안·개인정보 인수 기준 통과
- 합성 대시보드, 경보, 폴백, 기능 차단, 롤백 리허설 완료
- 제품·엔지니어링·QA·개인정보·보안 책임자 승인

## 8. post-MVP 검증 제안

실제 마이데이터 연동의 법무·보안·제공자 계약과 별도 Go/No-Go가 끝난 뒤, 동의한 사용자 최대 100명을 대상으로 4주 검증을 제안할 수 있다. 이는 MVP 완료 후 새 계획·인수 기준·중단 권한을 승인받아 수행하며 현재 MVP의 합격 조건이나 완료 증거가 아니다.

post-MVP 단계 확대에서는 잘못된 ID·수치·개인정보·투자 유도 노출 1건, 철회 SLA 위반 1건, 목표 확정 오류율 1% 초과, 계산 불일치 신고율 2% 초과 시 확대를 중단한다. AI만 문제면 즉시 결정론적 폴백으로 전환하고 핵심 목표 기능은 유지한다. D7·D28·4주 KPI는 각 관찰창이 완전히 닫힌 동의 코호트만 보고하며 MVP 합성 결과와 섞지 않는다.
