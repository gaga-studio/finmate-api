# FinMate vNext 화면 명세

## 1. 공통 화면 계약

- 모든 금융값 화면은 `데이터 상태 · 마지막 동기화 · 검증 출처`를 같은 정보 묶음으로 제공한다.
- 최초 로딩은 화면 구조와 같은 스켈레톤을 사용하고, 갱신은 기존 값을 유지한 채 해당 영역에만 진행 상태를 표시한다.
- 오류는 저장된 최신 성공 데이터를 지우지 않는다. 쓰기 오류는 자동 재실행하지 않고 사용자가 다시 확인한다.
- `오래됨`에서는 진행률 계산과 레이드 연출을 멈춘다. `반영 대기`에서는 이전 검증값을 유지한다.
- 동의가 필요한 행동은 목적·항목·보관 또는 공개 범위·철회 경로를 행동 전에 보여준다.
- 목표 확인 화면은 현재 동의·연결·후보 상태를 확정 직전에 재검증한다. 동의 변경·철회와 오프라인에서는 확정 요청을 보내지 않고, 재동의 또는 재연결 뒤 사용자의 새 확정을 요구한다.
- 화면의 API 열은 URL이 아니라 `prd.md`의 역량 이름을 사용한다.

## 2. 화면별 명세

### OB-01 온보딩 프로필

- **목적**: 목표 계산과 추천에 필요한 생활맥락, 돈 고민, 변화 성향, 투자 위험성향을 수집한다.
- **주요 행동**: 이전/다음, 단일·복수 선택, 알림 선호 설정, 입력 내용 수정.
- **API 역량**: `온보딩 프로필 관리`.
- **로딩**: 저장된 답변을 불러오는 동안 현재 단계 스켈레톤과 단계 수만 표시한다.
- **빈 상태**: 필수 질문은 선택 전 `다음`을 비활성화하고 필요한 이유를 입력 아래에 표시한다.
- **오류**: 단계 저장 실패 시 입력을 보존하고 `다시 저장`을 제공한다.
- **오래됨**: 해당 없음. 30일 넘게 중단한 온보딩은 기존 답변을 보여주고 최신 여부를 다시 확인한다.
- **동의**: 투자 위험성향은 목표가 아니라 교육·점검 개인화에 쓰임을 입력 전에 고지한다.
- **수용 기준**: 키보드만으로 모든 선택과 단계 이동이 가능하고, 뒤로 이동해도 답변이 유지된다.

### OB-02 공개 설정과 마이데이터 연결

- **목적**: 선택적 익명 카드 공개와 필수 마이데이터 연결을 구분해 사용자가 통제하게 한다.
- **주요 행동**: 공개 항목 펼쳐보기, 공개 동의 켜기/끄기, 수집 항목 확인, 연결, 나중에 계속.
- **API 역량**: `동의 및 공개 범위 관리`, `마이데이터 연결 관리`.
- **로딩**: 연결 기관 목록과 기존 동의 상태를 별도 스켈레톤으로 표시한다.
- **빈 상태**: 연결 가능한 기관이 없으면 이유와 지원 채널을 보여주며 정량 진단은 시작하지 않는다.
- **오류**: 인증 취소와 시스템 오류를 구분하고 재연결 또는 온보딩 종료를 제공한다.
- **오래됨**: 이전 연결 정보가 만료되었으면 재인증 필요와 마지막 성공 시각을 표시한다.
- **동의**: 수집 동의와 공개 동의를 별도 체크로 받고 사전 선택하지 않는다. 공개 거절은 개인 기능을 제한하지 않는다.
- **수용 기준**: 사용자가 공개/비공개 항목과 철회 경로를 연결 전에 확인할 수 있다.

### OB-03 기준선 진단

- **목적**: 초기 금융 기준선, 네 동물의 역할, 데이터 신뢰 상태를 설명한다.
- **주요 행동**: 소득·필수지출 분류 확인, 확인 필요 거래 보기, 홈으로 이동.
- **API 역량**: `금융 기준선 진단`, `거래 분류 확인`.
- **로딩**: 진단 단계 이름과 진행 상태를 표시하고 결과 수치를 추정해 보여주지 않는다.
- **빈 상태**: 데이터 부족 또는 여윳돈 0 이하이면 이유와 가능한 행동형 시작 경로를 제시한다.
- **오류**: 계산 실패 범위와 재시도를 제공하고 원본 거래를 화면에 노출하지 않는다.
- **오래됨**: 연결 직후에도 기준 데이터가 오래되면 정량 후보 제한을 명시한다.
- **동의**: 진단에 사용된 수집 항목과 연결 철회 진입점을 제공한다.
- **수용 기준**: 금융 스탯, 목표 진행률, 퀘스트 XP가 서로 다른 값임을 화면에서 구분할 수 있다.

### H-01 홈·자동 레이드

- **목적**: 활성 목표, 현재·최고 진행률, 레이드 단계, 데이터 상태, 다음 행동을 한 화면에서 확인하게 한다.
- **주요 행동**: 목표 찾기, 동물 리포트 열기, 다음 퀘스트 열기, 목표 메뉴, 연결 상태 확인.
- **API 역량**: `홈 요약 조회`, `목표 진행률 조회`, `목표 생명주기 관리`.
- **로딩**: 마지막 홈이 있으면 유지하고 갱신 배지만 표시한다. 최초에는 레이드·목표·다음 행동 구조의 스켈레톤을 사용한다.
- **빈 상태**: 목표가 없으면 빈 전투장, 네 동물, `목표 찾기`만 우선 제공한다.
- **오류**: 레이드와 목표 조회 오류를 분리하고 마지막 성공 시각과 `다시 시도`를 표시한다.
- **오래됨**: 전투를 멈추고 이전 진행률, 마지막 동기화, `연결 상태 확인`을 표시한다. 반영 대기에는 예상 시간이 아닌 전송 주기를 안내한다.
- **동의**: 연결 철회 상태라면 재연결 전까지 읽기 전용 기록만 제공한다.
- **수용 기준**: 보스 HP가 현재 단계 진행률과 일치하고, 진행률 하락 시 해금 단계와 최고 진행률이 유지된다.

### M-01 비교 탐색

- **목적**: 나와 출발점이 비슷하고 공개 검증을 통과한 루틴 출처를 발견하게 한다.
- **주요 행동**: 목표 영역 선택, 공개 가능한 조건 필터, 카드 넘기기, 성장 방식 보기.
- **API 역량**: `추천 모험가 탐색`.
- **로딩**: 카드 높이를 고정한 스켈레톤 3개와 필터를 표시한다.
- **빈 상태**: 정확 코호트가 30명 미만이면 개인 카드를 숨기고 비금융 생활맥락만 넓힌다. 30명 이상 안전 일반화 코호트를 찾으면 개인 필드 없는 `GROUP_ROUTINE`을 표시한다. 끝까지 30명 미만이면 `INSUFFICIENT`와 카드 없는 빈 상태에서 조건 완화 순서와 다른 목표 영역을 제시한다.
- **오류**: 저장된 카드가 있으면 기준일과 함께 유지하고 새 추천만 재시도한다.
- **오래됨**: 카드 기준일이 허용 범위를 넘으면 선택을 막고 추천 갱신을 요청한다.
- **동의**: 추천에 사용한 내 생활맥락 범위와 상대 카드의 공개 동의 배지를 확인할 수 있다.
- **수용 기준**: 카드에 정확 금액·상품·종목·수익률이 없고 유사 이유 2~3개가 구체적 문장으로 표시된다. 정확 코호트가 30명 미만일 때는 개인 닉네임·외형·유지기간이 없으며, `cohortSize >= 30`인 안전 그룹 루틴만 표시한다. 안전 코호트가 없으면 카드가 한 장도 표시되지 않는다.

### M-02 추천 모험가 상세·성장 방식

- **목적**: 추천 모험가의 공개 루틴, 유지기간, 검증 근거를 이해하고 따라 할 루틴 하나를 선택하게 한다.
- **주요 행동**: 루틴 선택, 공개 범위 보기, 기준일 확인, 목표 후보 만들기.
- **API 역량**: `추천 모험가 상세 조회`, `목표 후보 생성`.
- **로딩**: 카드 요약을 유지하고 루틴 목록만 스켈레톤으로 표시한다.
- **빈 상태**: 유효한 루틴이 사라지면 선택을 막고 비교 탐색으로 돌아간다.
- **오류**: 상세 불러오기 실패 시 카드 요약과 재시도만 제공한다.
- **오래됨**: 품질 또는 공개 상태가 만료되면 후보 생성을 막고 다른 모험가를 안내한다.
- **동의**: `금액 비공개 · 실제 루틴 · 공개 동의`와 공개 항목 설명을 상시 노출한다.
- **수용 기준**: `상대의 금액이 아니라 루틴과 유지 주기를 가져왔어요`가 후보 생성 전에 읽힌다.

### G-01 목표 후보 비교

- **목적**: 내 기준선으로 계산한 세 후보의 차이와 검증 방식을 비교하게 한다.
- **주요 행동**: 가볍게/표준/도전 선택, 계산 근거 펼치기, 기준 거래 확인, 선택 계속.
- **API 역량**: `목표 후보 생성`, `금융 기준선 진단`, `AI 순위·설명 생성`.
- **로딩**: 기준선 계산 단계를 표시하고 후보 숫자 자리를 임의 값으로 채우지 않는다.
- **빈 상태**: 정량 후보를 만들 수 없으면 이유와 승인된 행동형 시작 목표를 제공한다.
- **오류**: AI timeout·검증 오류는 `DETERMINISTIC_FALLBACK` 순위와 승인 문구로 바꾸고 후보를 막지 않는다. 계산 오류는 선택을 막고 다시 계산한다.
- **오래됨**: 기준 데이터가 오래되면 후보 확정을 비활성화하고 연결 상태 확인으로 이동한다.
- **동의**: 후보가 상대의 금액을 복사하지 않았고 어떤 데이터로 검증되는지 표시한다.
- **수용 기준**: 각 후보에 목표값/범위, 기간, 검증 출처, 기준일, 난이도 설명이 있으며 기준값과 같은 후보는 없다. 추천 후보와 근거·요약·위험 안내가 표시되고 `AI_GENERATED`와 `DETERMINISTIC_FALLBACK` 어느 상태에서도 후보 ID와 수치는 서버 후보 객체와 일치한다.

### G-02 목표 확인·확정

- **목적**: 선택한 목표와 데이터·동의 조건을 마지막으로 검토하고 활성 목표를 하나 생성한다.
- **주요 행동**: 목표 확정, 이전으로 돌아가 후보 변경, 기존 목표 교체 영향 확인, 변경 동의 재동의, 재연결 후 다시 확인.
- **API 역량**: `목표 생명주기 관리`, `동의 및 공개 범위 관리`, `감사 이력 기록`.
- **로딩**: 확정 중 버튼을 잠그고 한 번의 요청 상태를 명확히 표시한다.
- **빈 상태**: 후보가 만료되면 확정 대신 `최신 후보 다시 계산`을 제공한다.
- **오류**: 중복 오류는 활성 목표 조회로 성공 여부를 확인한 뒤 재시도한다. 네트워크 오류는 저장된 확인 정보를 읽기 전용으로 유지하고 확정 요청을 보내지 않는다.
- **오래됨**: 기준선 변경 감지 시 확정을 막고 변경된 값 비교로 이동한다.
- **동의**: 목표값, 기간, 검증 출처, 현재 동의 버전, 데이터 기준일을 한 화면에서 확인한다. 동의 버전이 바뀌면 변경 항목을 보여주고 재동의 후 후보·기준 데이터·연결 상태를 재검증한다. 필요한 동의 또는 연결이 철회되면 재동의·재연결·최신 후보 재계산을 안내한다.
- **오프라인**: `목표 확정`을 비활성화하고 저장된 후보·동의·기준일을 읽기 전용으로 표시한다. 재연결 뒤 현재 동의·연결·후보 상태를 새로 조회한 뒤에만 다시 확인할 수 있다.
- **수용 기준**: 반복 탭에도 활성 목표가 하나만 생성되고 성공 후 해당 목표의 홈으로 이동한다. 동의 변경 시 재동의와 재검증 전에는, 동의·연결 철회 시 재동의·재연결·최신 후보 재계산 전에는 확정 요청이 전송되지 않는다. 오프라인에서는 활성 목표가 생성되지 않고 재연결 뒤 사용자 재확정이 있어야만 생성된다.

### G-03 목표 관리

- **목적**: 활성 목표를 일시정지, 재개, 취소하거나 재설정한다.
- **주요 행동**: 일시정지, 재개, 취소, 새 기준선 비교, 새 후보 선택.
- **API 역량**: `목표 생명주기 관리`, `금융 기준선 진단`, `감사 이력 기록`.
- **로딩**: 현재 상태를 유지하고 선택한 작업에만 진행 표시를 한다.
- **빈 상태**: 활성 목표가 없으면 닫고 홈의 목표 없음 상태로 이동한다.
- **오류**: 상태 변경 실패 시 기존 상태를 유지하고 자동 재시도하지 않는다.
- **오래됨**: 30일 초과 일시정지 또는 기준선 20% 변화 시 즉시 재개를 막고 재설정을 제공한다.
- **동의**: 취소·교체가 기록과 추천 공개에 미치는 영향을 분리해 설명한다.
- **수용 기준**: 일시정지 중 목표 상태가 `일시정지`로 유지되고 진행률·레이드가 갱신되지 않는다. 목표 연결 퀘스트도 `일시정지`되어 완료 처리와 퀘스트 XP 지급이 중단된다. 포인트·현금성·경제적 보상은 MVP에 존재하지 않으며, 취소에 XP 차감·손실 표현이 없다.

### Q-01 퀘스트 목록

- **목적**: 오늘의 목표 연결 행동과 참여 가능·진행 중·대기·완료 상태를 훑어보게 한다.
- **주요 행동**: 상태 필터, 퀘스트 열기, 진행 중 행동 이어하기.
- **API 역량**: `퀘스트 목록 및 검증`.
- **로딩**: 오늘 요약과 카드 구조의 스켈레톤을 사용한다.
- **빈 상태**: 활성 목표가 없으면 목표 찾기, 오늘 퀘스트가 없으면 최근 완료와 다음 갱신 기준을 보여준다.
- **오류**: 저장된 목록과 기준일을 유지하고 새로고침을 제공한다.
- **오래됨**: 금융 데이터 검증 퀘스트만 대기 처리하며 앱 활동 퀘스트는 계속 사용할 수 있다.
- **동의**: 각 퀘스트 상세에서 검증 출처를 확인할 수 있음을 표시한다.
- **수용 기준**: 투자 판단 퀘스트에는 XP·보상·축하 표식이 없고 만료·취소에 손실 표현이 없다.

### Q-02 퀘스트 상세

- **목적**: 행동의 이유, 완료 조건, 검증 출처, 반영 범위를 이해하고 시작하게 한다.
- **주요 행동**: 시작, 앱 내 확인 완료, 취소, 데이터 반영 상태 확인.
- **API 역량**: `퀘스트 목록 및 검증`, `감사 이력 기록`.
- **로딩**: 제목을 유지하고 조건·상태 영역만 갱신한다.
- **빈 상태**: 퀘스트가 만료·삭제되었으면 상태와 기록 유지 여부를 설명하고 목록으로 이동한다.
- **오류**: 완료 검증 실패 시 행동 기록을 보존하고 다시 확인한다.
- **오래됨**: 금융 행동은 `데이터 반영 대기`로 두고 완료 처리하지 않는다.
- **동의**: 앱 밖 금융 행동을 직접 수행시키지 않으며, 필요한 데이터 항목과 확인 방식을 보여준다.
- **수용 기준**: 완료가 금융 스탯 또는 보스 피해로 자동 환산되지 않고 실제 반영 조건이 별도로 표시된다.

### R-01 동물별 금융 리포트

- **목적**: 선택한 영역의 현재 상태, 산정 이유, 추세, 목표 연결, 다음 행동을 설명한다.
- **주요 행동**: 동물 탭 전환, 산정 이유 펼치기, 확인 필요 거래 보기, 다음 행동 열기.
- **API 역량**: `동물별 금융 리포트 조회`, `거래 분류 확인`.
- **로딩**: 선택 동물과 마지막 값은 유지하고 차트·설명만 갱신한다.
- **빈 상태**: 데이터 부족 영역은 필요한 데이터와 행동형 학습을 제시한다.
- **오류**: 수치와 산정 이유 조회 오류를 분리하며 설명 영역 실패가 핵심 지표를 가리지 않는다.
- **오래됨**: 추세 마지막 지점을 기준일로 고정하고 계산 중지 배너를 표시한다.
- **동의**: 리포트 사용 데이터와 연결 관리 진입점을 제공한다.
- **수용 기준**: 토끼 리포트에 평가손익·수익률 순위·거래 횟수·매수매도 추천이 없다.

### J-01 30일 금융 여정

- **목적**: 최근 금융 활동과 목표 변화를 날짜 순서로 회고하게 한다.
- **주요 행동**: 월 이동, 날짜 선택, 목표·단계 이력 보기, 회고 작성.
- **API 역량**: `금융 여정 기록 조회`.
- **로딩**: 월 헤더와 발판 위치를 고정한 스켈레톤을 사용한다.
- **빈 상태**: 기록이 없으면 연결 상태를 확인하고 첫 앱 기록 행동을 제공한다.
- **오류**: 로컬에 남은 월 요약을 유지하고 해당 월만 재시도한다.
- **오래됨**: 금융 활동은 기준일까지 표시하고 이후 날짜는 미수집으로 구분한다.
- **동의**: 기록에 포함된 데이터 범위와 보존되는 목표 이력을 설명한다.
- **수용 기준**: 날짜 발판에 대표 활동 1개, 보조 최대 2개, 나머지 `+N`을 표시하며 내부이체는 대표 활동에서 제외한다.

### J-02 일일 기록 상세

- **목적**: 선택 날짜의 수입·지출·저축·투자 내역, 예산, 퀘스트, 스탯 반영 여부를 확인한다.
- **주요 행동**: 거래 분류 확인, 관련 목표 이력 열기, 한 줄 기록 작성.
- **API 역량**: `금융 여정 기록 조회`, `거래 분류 확인`.
- **로딩**: 바텀시트 높이를 고정하고 섹션별 스켈레톤을 사용한다.
- **빈 상태**: 해당 날짜 활동이 없으면 `확인된 금융 활동이 없어요`와 앱 기록만 제공한다.
- **오류**: 실패 섹션만 재시도하고 다른 섹션은 유지한다.
- **오래됨**: 미도착 가능성을 설명하며 활동 없음과 데이터 미수집을 구분한다.
- **동의**: 민감 거래 원문은 기본 축약하고 사용자의 상세 열기 행동 후 보여준다.
- **수용 기준**: 각 활동이 금융 스탯, 목표 진행률, 퀘스트 XP 중 어디에 반영됐는지 구분된다.

### C-01 거래 분류 확인

- **목적**: 충돌·중복·이상 거래를 사용자가 확인하고 계산의 신뢰도를 높인다.
- **주요 행동**: 카테고리 선택, 내부이체/환불/대출/재예치 표시, 변경 저장, 재계산.
- **API 역량**: `거래 분류 확인`, `금융 기준선 진단`, `감사 이력 기록`.
- **로딩**: 거래 식별 정보는 유지하고 선택지 영역만 로딩한다.
- **빈 상태**: 확인할 거래가 없으면 완료 메시지 후 이전 화면으로 돌아간다.
- **오류**: 저장 실패 시 선택을 보존하고 재계산을 시작하지 않는다.
- **오래됨**: 최신 동기화가 필요한 거래는 수정 대신 연결 상태 확인을 안내한다.
- **동의**: 수정값의 계산 사용 범위와 되돌리기 경로를 저장 전에 설명한다.
- **수용 기준**: 확인 전 거래는 목표 계산에서 제외되고 변경 후 스냅샷에 사용자 수정 이유가 남는다.

### S-01 동의·연결 관리

- **목적**: 마이데이터 연결과 익명 카드 공개를 독립적으로 조회·변경·철회하게 한다.
- **주요 행동**: 수집 항목 보기, 연결 갱신/철회, 공개 범위 변경/철회, 처리 상태 확인.
- **API 역량**: `동의 및 공개 범위 관리`, `마이데이터 연결 관리`, `감사 이력 기록`.
- **로딩**: 현재 동의 요약을 유지하고 상태만 갱신한다.
- **빈 상태**: 연결 없음과 공개 비동의를 정상 상태로 설명하고 필요한 경우에만 연결 CTA를 제공한다.
- **오류**: 철회 요청은 같은 `Idempotency-Key`로만 재확인한다. `412 PRECONDITION_FAILED`이면 최신 `consentAggregateId`·version을 다시 읽고, 철회된 aggregate의 이전 opt-in을 재전송하지 않는다.
- **오래됨**: 동의 버전이 바뀌면 새 항목과 기존 항목의 차이를 먼저 보여준다.
- **동의**: 체크를 사전 선택하지 않고 철회 효과, 캐시 제거 최대 24시간, 개인 기록 유지 범위를 명시한다.
- **수용 기준**: 공개 철회가 마이데이터 연결을 끊지 않고, 연결 철회 후 목표·기록은 읽기 전용으로 남는다. 철회와 지연된 opt-in이 경합해도 화면은 `WITHDRAWN`을 유지하며 다시 켜려면 새 aggregate에 명시적으로 동의한다.

## 3. 단계 완료 오버레이

- **목적**: 33%, 66%, 100% 검증 시 단계 해금 또는 목표 완료를 짧게 알린다.
- **행동**: 계속, 기록 보기. 닫기를 항상 제공한다.
- **API 역량**: `목표 진행률 조회`, `금융 여정 기록 조회`.
- **상태**: 네트워크 오류 시 연출은 생략하고 기록 배지만 나중에 표시한다. 오래된 데이터에서는 실행하지 않는다.
- **접근성**: 동작 줄이기에서는 정적 전환과 텍스트 알림만 사용하며 초점은 오버레이 제목으로 이동한다.
- **수용 기준**: 투자 판단 목표에는 외형 성장·보상·축하 효과가 없고 완료 사실과 설명만 표시된다.

## 4. 전 화면 검수 기준

1. 320px 너비와 200% 확대에서 핵심 정보와 행동이 잘리거나 겹치지 않는다.
2. 모든 아이콘 버튼에 접근 가능한 이름과 툴팁이 있다.
3. 오류·오래됨·반영 대기·확인 필요를 색상만으로 구분하지 않는다.
4. 모달·바텀시트는 초점 가두기, 닫기, 복귀 초점을 지원한다.
5. 금액·비율에는 단위와 기준 기간이 있으며 차트에는 텍스트 요약이 있다.
6. MVP 화면 어디에도 친구, 공개 순위, 금융상품, 종목, 쿠폰, 포인트, 재도전 횟수가 노출되지 않는다.
