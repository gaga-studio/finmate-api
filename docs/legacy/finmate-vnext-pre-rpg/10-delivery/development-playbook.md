# 개발 플레이북

## 1. 전달 원칙

- 금융 계산과 정책은 결정론적 코드가 소유하고 AI는 허용 후보의 순위 보조와 설명만 담당한다.
- 개인정보 최소화, 사용자 선택권, 접근성, 감사 가능성을 기능 완료의 일부로 본다.
- 친구·팔로잉과 메이트 찾기는 Phase 2다. MVP에는 비교 탐색만 구현한다.
- 투자 영역은 위험성향·분산 개념의 학습·점검·기록만 제공하며 거래·투자금·수익률에 성장이나 보상을 연결하지 않는다.
- 작은 수직 단위로 개발하고 API·이벤트·테스트·운영 계측을 함께 완료한다.
- 3~4주 MVP는 계약 호환 어댑터와 합성 데이터로 인수한다. 실제 마이데이터 수집, 운영 사용자 표본, 실제 KPI와 100명·4주 파일럿은 post-MVP 제안이며 완료 정의에 포함하지 않는다.

## 2. 작업 단위의 완료 정의

하나의 작업은 다음 증거가 모두 있을 때 완료다.

- 승인된 요구사항과 인수 기준에 연결된 구현
- 정상·경계·실패 경로의 단위 또는 통합 테스트
- API·이벤트·AI 스키마 변경 시 계약과 호환성 테스트
- 개인정보 필드·동의·보존·로그 영향 점검
- 키보드·스크린리더·동작 줄이기 영향 점검
- 구조화 로그, 지표, 오류 코드와 운영 경보
- 사용자 문구와 빈·로딩·반영 대기·오류·폴백 상태
- 리뷰 승인, CI 통과, 합성 스테이징 확인과 변경 기록

문서만 있고 실행 경로가 없거나, 정상 화면만 있고 실패·철회·폴백 상태가 없으면 완료로 보지 않는다.

## 3. 브랜치와 변경 관리

- `main`은 배포 가능한 상태를 유지한다.
- 작업 브랜치는 `codex/`, `feature/`, `fix/`, `chore/` 중 팀이 선택한 접두사와 이슈 ID, 짧은 목적을 사용한다.
- 변경은 하루 안에 리뷰 가능한 크기를 목표로 하며 계산, 동의, AI, 분석 계약 변경을 한 PR에 무관하게 섞지 않는다.
- DB·API·이벤트는 추가 → 양쪽 읽기 → 생산자 전환 → 구버전 제거 순으로 변경한다.
- 목표 템플릿·계산 버전은 불변이다. 새 목표만 새 버전을 사용하고 활성 목표는 확정 버전으로 끝낸다.
- 생성 파일, 개인 설정, 비밀정보, 실제 고객 데이터는 커밋하지 않는다.

### 커밋

커밋 제목은 `feat:`, `fix:`, `test:`, `docs:`, `chore:`를 사용하고 한 가지 의도를 담는다. 본문에는 정책 결정, 데이터 마이그레이션, 롤백 영향이 있을 때만 그 근거를 기록한다. 포맷 변경과 동작 변경은 가능한 한 분리한다.

## 4. PR 규약

PR 설명에는 다음 항목을 채운다.

```markdown
## 변경 목적
사용자 문제와 요구사항 ID

## 동작 변화
정상·빈 상태·오류·폴백·철회 흐름

## 계약 변화
API, DB, 이벤트, AI 스키마와 버전 호환성

## 안전 점검
개인정보, 동의, 투자 게임화, 접근성 영향

## 검증 증거
자동 테스트, 스테이징 시나리오, 화면·로그·지표 확인

## 배포와 복구
기능 플래그, 관찰 지표, 중지 기준, 롤백 절차
```

### 필수 리뷰어

| 변경 | 필수 승인 |
| --- | --- |
| 계산·진행률·목표 상태 | 백엔드 도메인 책임자 + QA |
| 공개 카드·동의·삭제·보존 | 개인정보 책임자 + 보안 담당자 |
| AI 입력·프롬프트·모델·검증 | AI 책임자 + 백엔드 책임자 + QA |
| 분석 이벤트·KPI SQL | 데이터 책임자 + 개인정보 책임자 |
| 투자 영역·게임 연출·알림 | 제품 책임자 + 안전 리뷰어 |
| 접근성 핵심 컴포넌트 | 프론트엔드 책임자 + QA |

작성자는 자신의 PR을 단독 병합하지 않는다. 고위험 계약 변경은 코드 소유자 2명 이상이 승인한다.

## 5. CI 파이프라인

PR마다 다음 순서로 실행한다.

1. 포맷, 린트, 타입 검사, 비밀정보·금지어·PII 패턴 검사
2. 단위·공식·속성 테스트
3. JSON·YAML 파싱과 API·이벤트·AI 계약 테스트
4. 골든 테스트 전수 실행과 승인값 차이 출력
5. DB 마이그레이션 전진·후진 호환성 검사
6. 통합 테스트: 계약 호환 합성 금융데이터 어댑터, 동의, 카드, 목표, AI 폴백, 분석 큐
7. 핵심 E2E와 자동 접근성 검사
8. 의존성·정적 보안 스캔, 컨테이너 이미지 스캔
9. 변경 범위별 프리뷰 배포와 스모크 테스트

`main` 야간 빌드는 전체 브라우저·기기 행렬, 성능, 동적 보안, 철회·삭제 장애 주입, 이벤트 데이터 품질을 실행한다. 실패한 필수 게이트를 관리자 권한으로 우회하지 않는다. 긴급 수정도 최소 회귀와 사후 전체 검증을 거친다.

## 6. 개발 규칙

### 계산과 상태

- 금액은 정수 원 단위, 비율은 고정 소수 또는 명시한 정밀도로 계산하고 부동소수 암묵 반올림을 금지한다.
- 시간은 저장 시 UTC, 사용자 표시와 코호트 경계는 `Asia/Seoul`로 명시한다.
- 후보 확정·일시정지·재개·취소는 멱등성 키와 상태 전이 제약을 사용한다.
- 진행률 변경마다 계산 버전, 입력 기간, 제외 거래, 현재·최고 진행률을 스냅샷으로 남긴다.
- 데이터 부족·오래됨·확인 필요는 정상 상태이며 예외나 실패로 숨기지 않는다.

### 개인정보와 로그

- API·이벤트·로그는 허용 목록 직렬화를 사용한다.
- 정확 금융값과 거래 원문은 일반 로그, 분석 이벤트, AI 입력에 기록하지 않는다.
- 공개 동의는 별도 선택이며 철회 상태를 캐시보다 먼저 확인한다.
- 테스트·개발 환경은 합성 데이터만 사용하고 운영 데이터 내보내기를 금지한다.
- AI 감사 로그는 `OPERATIONAL`, `INCIDENT_EVIDENCE`, `LEGAL_REQUIRED` 분류와 만료일을 강제하고 동의 철회·계정 삭제·백업 복원 테스트를 포함한다.
- 비밀정보는 관리형 저장소에서 런타임 주입하고 로컬 파일·PR·스크린샷에 남기지 않는다.

### AI

- 모델은 버전 고정 허용 목록을 사용하고 자동 업그레이드를 끈다.
- 입력은 승인된 ID·열거형·구간과 선택 카드·후보가 공급한 근거 코드·승인 문장으로만 구성한다.
- JSON 스키마, ID 허용 목록, 공급 근거 부분집합, 요약 주장 근거, 숫자 불변, 안전 문구 검사를 모두 통과한 응답만 노출한다.
- 실패 응답을 부분 복구하지 않고 전체를 폐기해 결정론적 폴백으로 전환한다.
- AI가 없어도 후보 비교·확정·거절·취소가 가능해야 한다.

### 프론트엔드와 접근성

- 로딩, 비어 있음, 반영 대기, 오래됨, 확인 필요, 오류, 오프라인, 폴백 상태를 구현한다.
- 키보드 초점, 명확한 레이블, 200% 확대, 320px 리플로, 명도 대비, 동작 줄이기를 컴포넌트 테스트에 포함한다.
- 레이드 연출 강도는 금융 기능과 독립적이며 사용자가 줄이거나 끌 수 있다.
- 데이터 기준일과 상태를 목표·홈·리포트 화면에 일관되게 표시한다.

## 7. 기능 플래그와 환경 설정

| 플래그 | 기본값 | 장애 시 |
| --- | --- | --- |
| `ai_explanations_enabled` | 합성 스테이징 `true` | `false`로 바꾸고 결정론적 설명 제공 |
| `anonymous_cards_enabled` | 합성 카드 인덱스에서 `true` | 전체 카드 인덱스 조회 차단, 목표·기록 유지 |
| `goal_confirmation_enabled` | 스테이징 검증 후 `true` | 새 확정 차단, 기존 목표 조회·일시정지·취소 유지 |
| `raid_motion_enabled` | 사용자 설정을 따름 | 정적 진행 상태로 전환 |
| `product_analytics_enabled` | 동의 사용자만 | 수집 중단, 운영 감사 스트림 유지 |

친구·팔로잉과 메이트 찾기 플래그는 MVP 설정에 등록하지 않는다. Phase 2 착수 시 개인정보·위협 모델을 갱신한 뒤 별도 도입한다.

## 8. MVP 릴리스 절차

1. 릴리스 후보를 고정하고 변경 로그, 스키마·마이그레이션, 기능 플래그를 확인한다.
2. QA가 계약 호환 어댑터·합성 데이터로 실행한 골든·E2E·접근성·성능·보안 결과를 첨부한다.
3. KPI는 `KPI-TRANSFORM-001` 등 고정 픽스처의 변환 기대값만 대조하고 실제 달성률을 합격 근거로 쓰지 않는다.
4. 제품·엔지니어링·QA·개인정보·보안 책임자가 합성 MVP 체크리스트를 승인한다.
5. 스테이징에서 기능 플래그 차단, AI 폴백, 철회·삭제, 백업 복원과 롤백을 장애 주입으로 리허설한다.
6. 실제 마이데이터 자격증명·실제 고객 데이터·운영 동의 표본이 없음을 확인하고 MVP 프로토타입 아티팩트를 고정한다.
7. 합성 인수 결과와 알려진 제한을 프로토타입 책임자에게 인계한다.

실제 제공자 연결과 5%·25%·100% 단계 확대 또는 100명·4주 파일럿은 post-MVP 별도 릴리스 계획이다. 개인정보·법무·보안 재승인, 실제 연동 계약 테스트와 새 Go/No-Go 없이는 위 MVP 절차에서 이어서 실행하지 않는다.

### 즉시 중지 조건

- 비허용 개인정보 노출 1건
- AI의 허용되지 않은 후보 ID·수치 노출 1건
- 투자 거래·금액·수익률을 유도하는 성장·보상·축하 1건
- 공개 철회 후 24시간 초과 노출 1건
- 중복 활성 목표 또는 계산 데이터 손상 1건
- 목표 확정 오류율 1% 초과 또는 계산 불일치 신고율 2% 초과

AI 문제는 AI 플래그를 끄고 폴백으로 유지한다. 공개 카드 문제는 카드 조회를 차단하되 개인 목표·기록을 보존한다. 계산 또는 동의 무결성 문제는 새 목표 확정을 중지하고 읽기·취소 경로를 유지한다.

MVP에서는 위 조건을 합성 장애 주입의 기대 차단 결과로 검증한다. 실제 사용자 노출과 비율 조건은 post-MVP 운영에서 같은 우선순위로 적용한다.

## 9. 롤백과 사고 대응

- 모든 릴리스에는 이전 애플리케이션 이미지, 역호환 DB 스키마, 기능 플래그 복구값과 책임자를 기록한다.
- 파괴적 마이그레이션은 같은 릴리스에서 실행하지 않고 두 번의 안정 릴리스 뒤 제거한다.
- 롤백 후 이벤트 소비자와 작업 큐가 구버전 메시지를 안전하게 처리하는지 확인한다.
- 사고는 탐지, 기능 차단, 영향 확인, 증거 보존, 통지 판단, 복구, 재발 방지 테스트 순으로 처리한다.
- S1 사고는 30분 안에 제품·엔지니어링·개인정보·보안 책임자를 소집하고 24시간 안에 영향과 임시 조치를 내부 공유한다.

## 10. 인계

MVP 인계 문서에는 프로토타입 소유자, 합성 대시보드, 경보 시뮬레이션, 실행 절차, 기능 플래그, 합성 어댑터, 데이터 보존·삭제 작업, AI 제공자 상태, 알려진 위험과 연락 체계를 포함한다. 실제 운영으로 전환하는 post-MVP 계획에는 SLO, 온콜, 철회 SLA, AI 안전, 계산 신고, 월 1회 삭제·복원 리허설과 분기 1회 사고 대응 연습을 별도로 승인한다.
