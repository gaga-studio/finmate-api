## 1. 제품 정의

### 서비스 한 줄

> 나와 비슷한 익명 모험가의 금융 루틴을 내 상황에 맞게 가져와, 실제 금융행동을 퀘스트와 레이드로 이어가는 금융 습관 앱

### 추상화 본질

> 금융진입장벽을 느끼는 청년들에게 사회적 호기심과 동기를 유발하여 금융친화력을 길러준다.

### 해결하려는 문제

- 금융 초보 청년은 정보가 부족해서보다 무엇부터 실행해야 하는지 몰라 행동을 미룬다.
- 평균이나 상위 사용자와의 단순 비교는 압박감을 만들고 실천 방법을 알려주지 못한다.
- 금융교육, 자산관리, 습관 기록이 분리되어 있어 배운 내용을 반복 행동으로 연결하기 어렵다.

### 핵심 가치

- `사회적 호기심`: 나와 비슷한 익명 모험가의 실제 루틴을 발견한다.
- `개인화`: 상대의 금액을 복사하지 않고 내 상황에 맞는 강도로 조정한다.
- `행동 전환`: 루틴을 오늘 실행할 수 있는 퀘스트로 바꾼다.
- `검증된 성장`: MVP에서는 검증된 합성 금융데이터가 바뀐 뒤에만 목표와 레이드가 진행된다.
- `이해 가능한 금융`: 캐릭터, 레이드, 기록을 통해 금융 상태를 쉽게 읽는다.

### 대상 사용자

- 금융관리를 시작하고 싶지만 기준을 잡기 어려운 19~34세 청년
- 복잡한 금융 용어보다 구체적인 행동 예시가 필요한 사용자
- 경쟁·수익률 중심 서비스보다 생활관리와 작은 성취를 원하는 사용자

## 2. MVP 사용자 경험

### 대표 흐름

`가입 → 합성 금융데이터 확인 → 주 목표 확정 → 홈 레이드 → 메이트 탐색 → 익명 모험가 선택 → 루틴 확인 → 적용 영역 선택 → 난이도 선택 → 루틴 적용 → 퀘스트 실행 → 데이터 반영 → 레이드 진행 → 기록 확인`

유럽 여행자금 `현재 200만원 → 목표 500만원 · 목표 2027년 1월`은 MVP의
대표 시연 사례다. 제품의 목표 도메인은 여행자금에 한정하지 않는다.

### 핵심 용어

| 용어 | 의미 |
| --- | --- |
| 목표 | 사용자가 온보딩에서 확정하는 하나의 중기 금융 결과 |
| 레이드 | 목표 진행률을 RPG 전투로 보여주는 시각화 |
| 메이트 | 비슷한 생활·금융 조건을 가진 익명 사용자 또는 그룹 |
| 루틴 | 메이트가 일정 기간 유지한 소비·저축·투자 판단 행동 |
| 루틴 적용 | 상대 루틴을 내 상황에 맞는 강도로 변환해 가져오는 과정 |
| 퀘스트 | 루틴을 실행하기 위한 일일·주간 행동 |
| 기록 | 퀘스트, 루틴, 금융데이터 변화와 회고를 날짜별로 보는 영역 |

### 제품 인과관계

`퀘스트 완료 → XP·내부 보상`

`합성 금융데이터 동기화 → 금융 스탯 재계산 → 목표 진행률 변경 → 레이드 갱신`

퀘스트 완료만으로 저축액이나 금융 스탯이 임의로 증가해서는 안 된다.

## 3. 화면 구조와 기능

### 온보딩

- 이메일·비밀번호·표시 이름 가입 및 로그인
- 비밀번호 12~72자 검증
- 생활 패턴과 금융 상태 확인
- 합성 금융데이터 기준선 제공
- 하나의 주 목표 입력 및 명시적 확정
- 목표 금액, 현재 금액, 목표 월 검토
- 목표 확정 전 뒤로 이동해도 입력 초안 유지
- 목표 확정 후 홈으로 이동

### 홈

- 확정된 주 목표와 현재 진행률
- 현재 레이드 단계와 보스 상태
- 소비·저축·투자 판단 금융 스탯
- 마지막 금융데이터 동기화 시각
- 현재 적용 중인 루틴
- 다음 추천 퀘스트
- 데이터 반영 대기·오래됨·부족 상태 안내

레이드는 시간 경과나 반복 전투만으로 진행되지 않는다. 금융데이터가 새로
검증된 경우에만 진행 상태가 바뀐다.

### 메이트

- 유사 메이트 그룹 목록
- 그룹 안의 익명 추천 모험가
- 모험가가 유지한 루틴과 기간
- 운영 추천 그룹은 익명 적격 구성원 30명 이상
- 10명 그룹은 `syntheticDemo = true`인 시연 데이터에서만 허용하고 운영 집계에서 제외
- 적용 영역 선택: 소비, 저축, 투자 판단
- 루틴 난이도 선택
  - `LIGHT`: 부담이 적은 시작안
  - `STANDARD`: 기본 추천안
  - `CHALLENGE`: 더 적극적인 실행안
- 루틴 적용 및 기존 루틴 교체 확인

루틴을 적용해도 온보딩에서 확정한 주 목표는 변경되지 않는다. 활성 루틴은
사용자당 하나만 허용한다. 기존 루틴이 있으면 교체 화면에 현재 루틴과 새 루틴을
함께 표시한다. 취소하면 현재 루틴을 유지하고, 확정하면 기존 루틴을 보관한 뒤 새
루틴을 하나의 트랜잭션에서 활성화한다.

### 퀘스트

- 참여 가능한 퀘스트
- 진행 중 퀘스트
- 금융데이터 반영 대기 퀘스트
- 완료 퀘스트
- XP와 비현금성 내부 보상
- 현재 목표·루틴과 연결된 추천 행동

금융 증거가 필요한 퀘스트는 사용자가 행동을 마쳐도 즉시 금융 성장을 확정하지
않는다. 합성 금융데이터 재계산으로 검증될 때까지 `DATA_PENDING` 상태를 유지한다.

투자 영역은 위험성향 확인, 분산 개념 학습, 리포트 점검만 제공한다.
금융지식도 학습·점검 행동으로만 구성한다. 매수·매도, 투자금 증액, 수익률 경쟁,
수익률 전망은 퀘스트·목표·리포트로 만들지 않는다.

### 기록

- 월간 날짜 탐색
- 날짜별 퀘스트·루틴 활동
- 금융데이터 재계산 기록
- XP 변화
- 사용자 회고 작성·수정
- 월간 요약 리포트

회고는 금융 계산 결과를 바꾸지 않으며 별도 사용자 기록으로 저장한다.

### 하단 내비게이션

`홈 · 메이트 · 퀘스트 · 기록`

설정은 홈 헤더에서 진입하며 다섯 번째 탭을 추가하지 않는다.

## 4. 데이터·계약·안전 기준

### 핵심 공개 모델

- `UserGoal`
- `RecommendedAdventurerCard`
- `RoutineAdaptationCandidate`
- `ActiveRoutineBuild`
- `RaidView`
- `Quest`
- `DailyRecord`

### 데이터 표현

- 금액: 정수 KRW
- 비율: basis point 정수
- 시간: ISO 8601
- 계산 응답 필수 메타데이터
  - `calculationVersion`
  - `dataState`
  - `lastSyncedAt`

### 데이터 상태

- `FRESH`: 새 계산과 진행 반영 가능
- `PENDING`: 새로운 데이터 반영 대기
- `STALE`: 데이터가 오래되어 새로운 진행 반영 중지
- `INSUFFICIENT`: 계산에 필요한 데이터 부족

`STALE`과 `INSUFFICIENT` 화면은 마지막 동기화 상태와 하나의 복구 행동을
제공한다. 데이터 상태 때문에 명령을 실행할 수 없는 경우 API는 RFC 7807 문제
응답과 구체적인 문제 코드를 반환한다.

### 메이트 공개 범위

- 익명 생활 맥락
- 루틴 유형과 유지 기간
- 범위화된 행동 정보
- 데이터 기준일

실명, 원천 사용자 식별자, 계좌번호, 정확 잔액, 거래 원문, 직장, 상세 위치,
투자 보유종목은 공개하지 않는다.

### AI·코치 정책

- 첫 버전은 LLM을 사용하지 않는다.
- 버전이 지정된 승인 문구 키와 결정적 규칙 기반 코치 메시지만 제공한다.
- 주 목표의 금액과 목표 월은 사용자가 입력·검토·확정하며, 확정된 값이 기준이다.
- API 코드는 목표값을 검증·저장하고 진행률과 개인화 루틴 후보를 결정적으로 계산한다.
- 코치 문구는 사용자가 확정한 목표값이나 API 계산 결과를 변경할 수 없다.
- 웹은 계산 결과를 재구현하지 않고 API 응답만 표현한다.

### 제외 범위

- 실제 마이데이터 연결
- 실제 투자·거래
- 투자상품 및 종목 추천
- 이메일 인증과 비밀번호 복구
- 현금·쿠폰·환금성 보상
- 공개 순위와 사용자 간 경쟁
- 생성형 AI 실시간 호출
- 운영환경의 데모 시간 진행 API

## 5. 제품 완료 기준과 팀 협업

### 대표 수용 기준

- 신규 사용자가 가입 후 하나의 목표를 확정하고 홈 레이드를 볼 수 있다.
- 사용자는 `그룹 → 익명 모험가 → 루틴` 순서를 건너뛰지 않고 탐색한다.
- 루틴 적용 후보는 `LIGHT·STANDARD·CHALLENGE`가 하나씩 제공된다.
- 세 후보는 사용자가 선택한 하나의 적용 영역과 모두 일치해야 한다.
- `INVESTMENT_JUDGMENT` 후보는 `behaviorTarget`만 사용하고 금액·비율 목표를 포함하지 않는다.
- 새 루틴 적용 시 현재 루틴과 새 루틴을 명시한 교체 확인이 반드시 나타난다.
- 교체 취소는 현재 루틴을 유지하고, 교체 확정은 기존 루틴을 보관·연결한 뒤 새 루틴을 원자적으로 활성화한다.
- 루틴 적용은 주 목표를 변경하지 않는다.
- 퀘스트 완료 직후 금융 스탯이 임의로 증가하지 않는다.
- 금융 증거 퀘스트는 합성 데이터 검증 전까지 `DATA_PENDING`을 유지한다.
- 합성 금융데이터 재계산 후에만 레이드와 금융 스탯이 갱신된다.
- 데이터 지연·부족 상태, 마지막 동기화 시각과 하나의 복구 행동이 화면에 표시된다.
- 데이터 상태가 명령을 차단하면 RFC 7807 문제 코드가 반환된다.
- 익명 모험가 카드에 원천 사용자 식별자가 노출되지 않는다.
- 금융지식과 투자 판단은 행동형만 허용하고 수익률 전망을 제공하지 않는다.
- 실제 투자 유도, 현금성 보상, 공개 순위가 어느 화면에도 나타나지 않는다.

### 검증 시나리오

- 가입·로그인·토큰 갱신·로그아웃
- 목표가 없거나 이미 활성 목표가 있는 경우
- 정상 메이트 그룹과 표본이 부족한 그룹
- 운영 그룹 30명 이상과 시연 전용 10명 그룹의 분리
- 루틴 최초 적용과 기존 루틴 교체
- 행동형 퀘스트 즉시 완료
- 금융데이터 검증 대기 퀘스트
- 금융지식·투자 판단 행동형과 금액·수익률 필드 차단
- 익명 모험가 응답의 원천 사용자 식별자 차단
- 오래되거나 부족한 데이터
- 날짜별 기록과 회고 수정
- 데모 환경 시간 진행과 운영환경 차단
- 모바일 360px·390px·430px 화면 검수

### 제품 지표

- 온보딩 목표 확정률
- 추천 모험가 카드에서 루틴 상세로 이동한 비율
- 루틴 후보 확인 후 적용률
- 첫 퀘스트 실행률
- 금융데이터로 검증된 첫 행동 완료율
- 4주 루틴 유지율
- 데이터 불일치 신고율
- 투자 유도·개인정보 노출 건수 `0건`

### 현재 개발 기준

- API 기준 저장소: `gaga-studio/finmate-api`
- 웹 저장소: `gaga-studio/finmate-web`
- 제품 문서와 OpenAPI는 API 저장소를 단일 원본으로 사용한다.
- 웹 API 타입과 클라이언트는 OpenAPI에서 생성한다.
- 두 저장소의 초기 MVP와 대표 E2E는 `main`에 병합된 상태다.

### 문서 운영 원칙

- 팀 공유 계획서의 원본은 `docs/vnext/01-product/team-product-plan.md`로 관리한다.
- 상세 제품 정책과 계약의 규범 원본은 `docs/vnext/README.md`의 우선순위를 따른다.
- 일반 정책 변경은 PR에서 관련 제품 문서, OpenAPI와 테스트를 함께 수정한다.
- 잠긴 결정을 변경하려면 새 ADR, 결정 로그, OpenAPI, 요구사항 추적표와 계약 테스트를 같은 PR에서 수정한다.
- Notion에는 원문을 복제하지 않고 문서 링크, 담당자, 진행 상태, 회의 결정만 기록한다.
- 발표자료에서 새로운 정책을 결정하지 않는다. 발표 내용은 확정된 제품 문서를 요약해야 한다.

## Assumptions

- 모바일 웹·PWA가 첫 출시 플랫폼이다.
- 첫 버전은 합성 금융데이터만 사용한다.
- 유럽 여행자금 목표는 대표 시연값이며 제품의 유일한 목표가 아니다.
- 팀원 이름별 담당 배정은 킥오프 회의에서 프론트·백엔드·데이터·제품 책임에 매핑한다.
- 실제 마이데이터, 생성형 AI, 외부 보상은 MVP 검증 이후 별도 안전·법무 검토를 거친다.
