# FinMate vNext 팀 공용 제품 기획서

> 문서 상태: MVP v1 팀 공용 진입 문서
>
> 이 문서는 기획·디자인·개발·데이터·QA·발표 참여자가 제품의 같은 그림을
> 보도록 돕는 시작점이다. 새로운 정책을 결정하는 규범 문서는 아니며, 상세
> 정책이 충돌하면 [`docs/vnext/README.md`](../README.md)의 규범 문서 우선순위를
> 따른다.

## 이 문서를 읽는 방법

처음 참여한 팀원은 먼저 `제품 정의 → 대표 흐름 → 전체 IA → 팀 공통 규칙`을
읽는다. 이후 맡은 업무에 따라 아래 영역을 확인한다.

| 참여 업무 | 우선 확인할 내용 | 이 문서에서 얻어야 하는 답 |
| --- | --- | --- |
| 기획 | 제품 정의, IA, 정책, MVP 범위, 수용 기준 | 무엇을 만들고 무엇을 만들지 않는가 |
| 디자인 | IA, 화면 목적, 대표 행동, 공통 상태, 금지 표현 | 각 화면이 어떤 질문에 답하고 어떤 상태까지 설계해야 하는가 |
| 개발 | 제품 인과관계, 상태 규칙, 팀 공통 규칙, 완료 조건 | 어떤 변화가 어떤 결과를 만들며 어디까지 연결되어야 하는가 |
| 데이터·QA | 금융 성장과 퀘스트 보상의 분리, 데이터 상태, 검증 시나리오 | 계산 전후와 예외 상황을 어떻게 구분하고 검증하는가 |
| 시연·발표 | 서비스 한 줄, 대표 흐름, 시연 사례, 제외 범위 | 현재 제품과 시연용 연출, 후속 계획을 어떻게 구분해 설명하는가 |

개인 이름별 역할은 이 문서에 고정하지 않는다. 팀은 아래의 업무 단계와 산출물,
승인 기준을 기준으로 협업한다.

## 1. 제품 정의

### 서비스 한 줄

> 나와 비슷한 익명 모험가의 금융 루틴을 내 상황에 맞게 가져와, 실제 금융행동을 퀘스트와 레이드로 이어가는 금융 습관 앱

### 추상화 본질

> 금융진입장벽을 느끼는 청년들에게 사회적 호기심과 동기를 유발하여 금융친화력을 길러준다.

### 해결하려는 문제

- 금융 초보 청년은 정보가 부족해서보다 무엇부터 실행해야 하는지 몰라 행동을 미룬다.
- 평균이나 상위 사용자와의 단순 비교는 압박감을 만들고 실천 방법을 알려주지 못한다.
- 금융교육, 자산관리, 습관 기록이 분리되어 있어 배운 내용을 반복 행동으로 연결하기 어렵다.

### 핵심 가치

- `사회적 호기심`: 나와 비슷한 익명 모험가의 실제 루틴을 발견한다.
- `개인화`: 상대의 금액을 복사하지 않고 내 상황에 맞는 강도로 조정한다.
- `행동 전환`: 루틴을 오늘 실행할 수 있는 퀘스트로 바꾼다.
- `검증된 성장`: MVP에서는 검증된 합성 금융데이터가 바뀐 뒤에만 목표와 레이드가 진행된다.
- `이해 가능한 금융`: 캐릭터, 레이드, 기록을 통해 금융 상태를 쉽게 읽는다.

### 대상 사용자

- 금융관리를 시작하고 싶지만 기준을 잡기 어려운 19~34세 청년
- 복잡한 금융 용어보다 구체적인 행동 예시가 필요한 사용자
- 경쟁·수익률 중심 서비스보다 생활관리와 작은 성취를 원하는 사용자

## 2. MVP 사용자 경험

### 대표 흐름

`가입 → 합성 금융데이터 확인 → 주 목표 확정 → 홈 레이드 → 메이트 탐색 → 익명 모험가 선택 → 루틴 확인 → 적용 영역 선택 → 난이도 선택 → 루틴 적용 → 퀘스트 실행 → 데이터 반영 → 레이드 진행 → 기록 확인`

유럽 여행자금 `현재 200만원 → 목표 500만원 · 목표 2027년 1월`은 MVP의 대표
시연 사례다. 제품의 목표 도메인은 여행자금에 한정하지 않는다.

### 핵심 용어

| 용어 | 의미 |
| --- | --- |
| 목표 | 사용자가 온보딩에서 확정하는 하나의 중기 금융 결과 |
| 레이드 | 목표 진행률을 RPG 전투로 보여주는 시각화 |
| 메이트 | 비슷한 생활·금융 조건을 가진 익명 사용자 또는 그룹 |
| 루틴 | 메이트가 일정 기간 유지한 소비·저축·투자 판단 행동 |
| 루틴 적용 | 상대 루틴을 내 상황에 맞는 강도로 변환해 가져오는 과정 |
| 퀘스트 | 루틴을 실행하기 위한 일일·주간 행동 |
| 기록 | 퀘스트, 루틴, 금융데이터 변화와 회고를 날짜별로 보는 영역 |

### 제품 인과관계

`퀘스트 완료 → XP·비현금성 내부 보상`

`합성 금융데이터 동기화 → 금융 스탯 재계산 → 목표 진행률 변경 → 레이드 갱신`

퀘스트 완료만으로 저축액이나 금융 스탯이 임의로 증가해서는 안 된다. 행동 완료와
금융 성장 확인은 서로 다른 사건이며, 화면과 문구에서도 명확히 구분한다.

## 3. 전체 IA

```text
앱 진입
├─ 회원
│  ├─ 회원가입
│  └─ 로그인
├─ 온보딩
│  ├─ 생활·금융 상태 확인
│  ├─ 합성 금융데이터 기준선 확인
│  ├─ 주 목표 입력
│  ├─ 목표 금액·기간 검토
│  └─ 목표 확정
└─ 메인
   ├─ 홈
   │  ├─ 주 목표와 진행률
   │  ├─ 레이드·금융 스탯
   │  ├─ 데이터 상태
   │  ├─ 활성 루틴
   │  ├─ 추천 퀘스트
   │  └─ 개인 리포트 요약·기록 진입
   ├─ 메이트
   │  ├─ 유사그룹
   │  ├─ 익명 모험가
   │  ├─ 루틴 상세
   │  ├─ 적용 영역 선택
   │  ├─ 난이도 비교
   │  └─ 루틴 적용·교체
   ├─ 퀘스트
   │  ├─ 참여 가능
   │  ├─ 진행 중
   │  ├─ 데이터 반영 대기
   │  └─ 완료
   └─ 기록
      ├─ 월간 기록
      ├─ 일별 상세
      ├─ 금융데이터 변화
      ├─ 퀘스트·루틴 활동
      ├─ 회고
      └─ 월간 요약

홈 헤더
└─ 설정

시연 전용
├─ 시간 진행
└─ 목표 완료 연출
```

- 인증과 온보딩을 마친 뒤 `홈 · 메이트 · 퀘스트 · 기록` 네 영역을 사용한다.
- 설정은 홈 헤더에서 진입한다.
- 시간 진행과 목표 완료 연출은 발표용 합성 시나리오에만 존재하며 일반 사용자
  탐색 구조와 분리한다.
- 실제 화면 목록이 바뀌면 먼저 화면 인벤토리에 차이를 기록하고, 제품 결정이
  끝난 뒤 이 IA에 반영한다.

### 핵심 사용자 흐름

1. `첫 사용`: 가입·로그인 → 합성 기준선 확인 → 주 목표 입력·검토 → 명시적 확정 → 홈
2. `루틴 가져오기`: 메이트 → 유사그룹 → 익명 모험가 → 루틴 상세 → 적용 영역 → 난이도 비교 → 적용
3. `행동형 퀘스트`: 퀘스트 실행·완료 → XP·내부 보상 → 완료 기록(금융 스탯과 레이드는 변경하지 않음)
4. `금융증거형 퀘스트`: 행동 완료 → XP·내부 보상 → 데이터 반영 대기 → 합성 금융데이터 재계산 → 실제 금융값이 바뀐 경우에만 홈 레이드 갱신
5. `기록 회고`: 기록 → 날짜 선택 → 활동·재계산 내역 확인 → 회고 작성·수정

## 4. 화면별 역할과 설계 원칙

| 영역 | 사용자가 확인하려는 것 | 핵심 콘텐츠 | 대표 행동 |
| --- | --- | --- | --- |
| 온보딩 | 현재 상태와 달성할 목표 | 기준선, 목표값, 목표 기간 | 목표 확정 |
| 홈 | 지금 어디까지 왔고 다음에 무엇을 할지 | 레이드, 스탯, 활성 루틴, 다음 퀘스트 | 퀘스트로 이동 |
| 메이트 | 비슷한 사람은 어떤 루틴을 유지하는지 | 익명 모험가, 루틴, 유지 기간 | 내 상황에 맞게 적용 |
| 퀘스트 | 오늘 실행할 작은 행동이 무엇인지 | 진행률, 검증 방식, 보상 상태 | 시작·완료 |
| 기록 | 어떤 행동과 데이터가 성장에 반영됐는지 | 일별 기록, 재계산, 회고 | 날짜 확인·회고 작성 |

한 화면은 하나의 핵심 질문과 대표 행동을 우선한다. 다른 영역의 주요 기능을 한
화면에 함께 넣어 탐색 구조를 흐리지 않는다.

### 온보딩

- 이메일·비밀번호·표시 이름으로 가입하고 로그인한다.
- 생활 패턴과 금융 상태를 확인한다.
- 합성 금융데이터 기준선을 제공한다.
- 하나의 주 목표를 입력하고 목표 금액, 현재 금액, 목표 월을 검토한다.
- 목표 확정 전 뒤로 이동해도 입력 초안을 유지한다.
- 목표를 명시적으로 확정한 뒤 홈으로 이동한다.

### 홈

- 확정된 주 목표와 현재 진행률을 보여준다.
- 현재 레이드 단계와 보스 상태를 보여준다.
- 소비·저축·투자 판단 금융 스탯을 보여준다.
- 마지막 금융데이터 동기화 시각과 현재 데이터 상태를 보여준다.
- 현재 적용 중인 루틴과 다음 추천 퀘스트를 보여준다.
- 개인 리포트 요약에서 스탯과 진행률 변화 이유를 짧게 보여주고, 상세 월간
  리포트는 기록으로 이동해 확인한다.

레이드는 시간 경과나 반복 전투만으로 진행되지 않는다. 금융데이터가 새로
검증된 경우에만 진행 상태가 바뀐다.

### 메이트

- 유사 메이트 그룹과 그룹 안의 익명 추천 모험가를 탐색한다.
- 모험가가 유지한 루틴, 유지 기간, 범위화된 행동 정보를 확인한다.
- 운영 추천 그룹은 익명 적격 구성원 30명 이상을 기준으로 한다.
- 10명 그룹은 합성 시연 데이터에서만 사용하고 운영 집계와 분리한다.
- 적용 영역은 소비, 저축, 투자 판단 중 하나를 선택한다.
- 난이도는 `LIGHT`(부담이 적은 시작안), `STANDARD`(기본 추천안),
  `CHALLENGE`(더 적극적인 실행안)로 비교한다.
- 적용 전 현재 루틴과 새 루틴을 함께 확인한다.

루틴을 적용해도 온보딩에서 확정한 주 목표는 변경되지 않는다. 활성 루틴은 하나만
허용하며, 교체를 취소하면 현재 루틴을 유지한다.

### 퀘스트

- 참여 가능, 진행 중, 데이터 반영 대기, 완료 상태를 구분한다.
- XP와 비현금성 내부 보상, 현재 목표·루틴과 연결된 추천 행동을 보여준다.
- 진행 중인 행동의 현재값, 목표값, 검증 방식과 남은 기간을 이해할 수 있게 한다.

금융 증거가 필요한 퀘스트는 사용자가 행동을 마쳐도 즉시 금융 성장을 확정하지
않는다. 합성 금융데이터로 검증될 때까지 데이터 반영 대기 상태를 유지한다.

투자 판단과 금융지식은 위험성향 확인, 분산 개념 학습, 리포트 점검 등 행동형으로만
구성한다. 매수·매도, 투자금 증액, 수익률 경쟁과 전망은 제공하지 않는다.

### 기록

- 월간 날짜 탐색과 날짜별 퀘스트·루틴 활동을 제공한다.
- 금융데이터 재계산과 XP 변화를 서로 구분해 보여준다.
- 사용자 회고를 작성·수정하고 월간 요약을 확인한다.

회고는 금융 계산 결과를 바꾸지 않으며 사용자가 남기는 별도 기록이다.

## 5. 공통 화면 상태와 사용자 안내

정상 데이터가 채워진 화면만으로는 완료로 인정하지 않는다. 기획과 디자인 단계부터
아래 상태의 정보 위계, 안내 문구와 다음 행동을 함께 정의한다.

| 상태 | 사용자에게 알려야 하는 것 | 화면 원칙 |
| --- | --- | --- |
| 로딩 | 데이터를 확인 중이라는 사실 | 이전 값을 새 값처럼 표시하지 않고 레이아웃 변화가 크지 않게 한다. |
| 빈 상태 | 무엇이 없으며 어떻게 시작하는지 | 원인 설명과 시작 행동 하나를 제공한다. |
| `PENDING` | 행동은 완료됐지만 금융데이터 검증을 기다리는 중 | 보상 완료와 금융 성장 대기를 분리해 표시한다. |
| `STALE` | 데이터가 오래되어 새 진행을 반영할 수 없음 | 마지막 동기화 시각과 복구 행동 하나를 제공한다. |
| `INSUFFICIENT` | 계산에 필요한 데이터가 부족함 | 부족한 정보와 대신 할 수 있는 행동형 시작 과제를 안내한다. |
| 오류 | 무엇이 실패했고 다시 할 수 있는지 | 실패 원인과 재시도 행동을 제공하며 입력값을 불필요하게 잃지 않는다. |
| 완료 | 무엇을 완료했고 무엇이 실제 성장으로 반영됐는지 | 퀘스트 보상과 금융 성장 결과를 분리한다. |
| 루틴 교체 확인 | 현재 루틴과 새 루틴의 차이 | 두 루틴을 함께 보여주고 취소하면 기존 루틴을 유지한다. |

모든 상태에서 사용자가 다음에 할 수 있는 행동은 하나가 가장 먼저 읽혀야 한다.

## 6. 데이터·안전 원칙

### 데이터 상태

- `FRESH`: 새 계산과 진행 반영이 가능하다.
- `PENDING`: 새로운 데이터 반영을 기다린다.
- `STALE`: 데이터가 오래되어 새로운 진행 반영을 멈춘다.
- `INSUFFICIENT`: 계산에 필요한 데이터가 부족하다.

계산 결과에는 계산 기준, 데이터 상태와 마지막 동기화 시각이 함께 제공되어야 한다.
구체적인 표현 형식과 개발 간 계약은 관련 상세 문서에서 관리한다.

### 메이트 공개 범위

- 익명 생활 맥락
- 루틴 유형과 유지 기간
- 범위화된 행동 정보
- 데이터 기준일

실명, 원천 사용자 식별 정보, 계좌번호, 정확 잔액, 거래 원문, 직장, 상세 위치,
투자 보유종목은 공개하지 않는다.

### 코치 정책

- 첫 버전은 생성형 AI를 사용하지 않는다.
- 승인된 문구와 결정적 규칙으로만 코치 메시지를 제공한다.
- 목표 금액과 목표 월은 사용자가 직접 입력·검토·확정한다.
- 계산과 진행률은 제품 규칙이 결정하며 코치 문구가 이를 변경하지 않는다.

### 제외 범위

- 실제 마이데이터 연결
- 실제 투자·거래와 상품·종목 추천
- 이메일 인증과 비밀번호 복구
- 현금·쿠폰·환금성 보상
- 공개 순위와 사용자 간 경쟁
- 생성형 AI 실시간 호출
- 일반 사용자에게 노출되는 시연용 시간 진행 기능

## 7. 팀이 혼동하면 안 되는 제품 규칙

- 목표는 온보딩에서 사용자 한 명당 하나만 확정한다.
- 메이트에서 가져오는 것은 목표가 아니라 실행 루틴이다.
- 활성 루틴은 하나이며 교체에는 사용자 확인이 필요하다.
- 퀘스트는 XP와 내부 보상을 제공하지만 금융 스탯을 직접 변경하지 않는다.
- 금융 스탯과 레이드는 검증된 합성 금융데이터 재계산으로만 변경된다.
- 투자 판단과 금융지식은 학습·점검 행동형만 제공한다.
- 익명 모험가의 정확 금액과 원천 사용자 정보는 노출하지 않는다.
- 어떠한 사용자 순위·리더보드, 현금성 보상, 수익률 전망과 거래 유도도 제공하지 않는다.
- 투자 판단을 전투 공격 수치로 표현하지 않는다.
- 현재 RPG 기준과 무관한 과거 공간형 콘셉트를 화면과 문서에 다시 섞지 않는다.
- 시연 전용 기능은 일반 사용자 화면과 제품 성과 지표에서 분리한다.

## 8. MVP 완료 기준과 검증

### 대표 수용 기준

- 신규 사용자가 가입 후 하나의 목표를 확정하고 홈 레이드를 볼 수 있다.
- 사용자는 `그룹 → 익명 모험가 → 루틴` 순서를 건너뛰지 않고 탐색한다.
- 루틴 적용 후보는 `LIGHT·STANDARD·CHALLENGE`가 하나씩 제공된다.
- 세 후보는 사용자가 선택한 하나의 적용 영역과 모두 일치해야 한다.
- 투자 판단 후보는 행동 목표만 사용하고 금액·비율 목표를 포함하지 않는다.
- 새 루틴 적용 시 현재 루틴과 새 루틴을 명시한 교체 확인이 나타난다.
- 교체 취소는 현재 루틴을 유지하고 교체 확정은 기존 루틴을 보관한 뒤 새 루틴을 활성화한다.
- 루틴 적용은 주 목표를 변경하지 않는다.
- 퀘스트 완료 직후 금융 스탯이 임의로 증가하지 않는다.
- 금융 증거 퀘스트는 합성 데이터 검증 전까지 데이터 반영 대기 상태를 유지한다.
- 합성 금융데이터 재계산 후에만 레이드와 금융 스탯이 갱신된다.
- 데이터 지연·부족 상태, 마지막 동기화 시각과 복구 행동이 화면에 표시된다.
- 익명 모험가 화면에 원천 사용자 식별 정보가 노출되지 않는다.
- 실제 투자 유도, 환금성 보상과 공개 순위가 어느 화면에도 나타나지 않는다.

### 검증 시나리오

- 가입·로그인·로그아웃
- 목표가 없거나 이미 활성 목표가 있는 경우
- 정상 메이트 그룹과 표본이 부족한 그룹
- 운영 그룹과 합성 시연 그룹의 분리
- 루틴 최초 적용과 기존 루틴 교체
- 행동형 퀘스트 즉시 완료
- 금융데이터 검증 대기 퀘스트
- 투자 판단·금융지식 행동형과 금액·수익률 표현 차단
- 익명 모험가의 원천 사용자 식별 정보 차단
- 오래되거나 부족한 데이터
- 날짜별 기록과 회고 수정
- 시연 환경의 시간 진행과 일반 사용자 환경의 분리
- 모바일 360px·390px·430px 화면 검수

### 제품 지표

- 온보딩 목표 확정률
- 추천 모험가 카드에서 루틴 상세로 이동한 비율
- 루틴 후보 확인 후 적용률
- 첫 퀘스트 실행률
- 금융데이터로 검증된 첫 행동 완료율
- 4주 루틴 유지율
- 데이터 불일치 신고율
- 투자 유도·개인정보 노출 건수 `0건`

## 9. 업무 단계별 진행 기준

개인 이름이 아니라 단계별 산출물과 승인 기준으로 진행 상황을 판단한다.

### 1단계. 제품 기준 확정

- 산출물: 팀 공용 계획서, IA, 용어, MVP·제외 범위
- 승인 기준: 목표·루틴·퀘스트·레이드·기록의 관계에 팀 내 이견이 없다.

### 2단계. 디자인 인수·감사

- 산출물: 원본 동결 기록, 화면 목록, 에셋 목록, `KEEP·REFINE·REBUILD·DROP` 분류
- 승인 기준: 모든 화면과 상태가 분류되고 누락 화면이 확인된다.

### 3단계. 화면 구조 통합

- 산출물: 공통 셸, 내비게이션, 화면별 정상·빈·오류·데이터 상태
- 승인 기준: IA의 모든 MVP 화면을 모바일에서 탐색할 수 있다.

### 4단계. 제품 동작 연결

- 산출물: 목표, 메이트 루틴, 퀘스트, 기록이 대표 흐름으로 연결된 결과
- 승인 기준: 루틴 적용이 목표를 바꾸지 않고 데이터 반영 전후가 구분된다.

### 5단계. 통합 검증

- 산출물: 대표 사용자 흐름 검증, 모바일 검수 결과, 금지 요소 검사 결과
- 승인 기준: 합성 응답과 실제 제품 동작 기준의 흐름이 동일하고 필수 상태가 모두 검증된다.

### 6단계. 시연·발표 준비

- 산출물: 결정적 시연 시나리오, 발표 자료, 주장·근거표
- 승인 기준: 현재 구현, 시연용 연출과 후속 계획이 발표에서 명확히 구분된다.

## Assumptions

- 모바일 웹·PWA가 첫 출시 플랫폼이다.
- 첫 버전은 합성 금융데이터만 사용한다.
- 유럽 여행자금 목표는 대표 시연값이며 제품의 유일한 목표가 아니다.
- 역할은 개인 이름이 아니라 업무 단계와 산출물로 표현한다.
- 친구·팔로잉, 실제 마이데이터, 생성형 AI, 외부 보상은 MVP IA에 포함하지 않는다.
- 7월 14일 디자인 인수 후 실제 화면과 차이가 발견되면 화면 인벤토리에 먼저 기록하고 제품 결정 후 IA에 반영한다.
