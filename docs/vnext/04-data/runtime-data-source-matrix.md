# FinMate 런타임 데이터 출처 매트릭스

이 문서는 각 화면이 어떤 합성데이터를 읽고, 어디에서 값을 계산하며, 데이터가
부족할 때 무엇을 보여주는지 정리한다. 웹은 아래 계산을 재구현하지 않고 API 응답만
표현한다.

| 화면·기능 | 런타임 원본 | 계산·결합 주체 | 부족·지연 처리 |
| --- | --- | --- | --- |
| 온보딩 기준선 | 연결 페르소나, 정제 금융활동, 생활맥락 projection | API가 최근 완료월의 소득·필수지출·여윳돈·소비율·저축률을 계산 | 분모가 없거나 여윳돈이 0 이하이면 `INSUFFICIENT` |
| 홈 금융 상태 | 정제 금융활동, behavior·budget projection, 활성 목표 | API가 최신 검증 스냅샷으로 스탯·목표 진행률·레이드를 계산 | 총자산 원본이 없으면 `null`; 동기화 전에는 이전 값을 새 값처럼 표시하지 않음 |
| 동물별 리포트 | 월별 금융활동과 퀘스트 이력 | API가 실제 월별 스냅샷과 산정 이유를 구성 | 임의의 과거 점수를 만들지 않고 비어 있는 월을 제외 |
| 메이트 그룹 | feature·cluster profile projection | API가 그룹 범위와 산정 인원을 표시용 모델로 변환 | `scoredFriendCount`와 전체 인원을 구분 |
| 비교 탐색 | 공개 동의 페르소나, feature·behavior·routine projection | API가 자격 조건, 유사도, 완화 순서와 정렬을 적용해 최대 6명 반환 | 실제 후보만 반환하고 부족분을 fixture로 채우지 않음 |
| 모험가 상세·리포트 | 검색 결과의 opaque ID가 가리키는 persona·routine·group projection | API가 검색 카드와 같은 출처를 사용해 범위화된 지표를 구성 | 검색 자격을 잃거나 철회되면 상세·루틴 조회도 차단 |
| 루틴 적용 | 승인된 routine projection, 사용자 기준선, 앱 목표 정책 | API가 추천 후보를 사용자 값에 맞춰 가공 | 상품·종목·매매 시점은 후보에서 제외 |
| 친구·피드·연속기록 | friendships·feed_events·streaks projection | API가 읽기 전용·금액 없는 소셜 응답으로 변환 | 쓰기 기능과 정확 금융값은 제공하지 않음 |
| 퀘스트 | 앱 소유 템플릿, quest log, 금융활동 증거 | API가 수락·행동 완료·금융증거 대기를 분리 | 퀘스트 XP는 즉시 가능하지만 금융 스탯은 동기화 후 재계산 |
| 기록 월·일 상세 | 금융활동, 퀘스트 완료, 목표·재계산 이벤트, 회고 | API가 날짜별로 결합하고 절대금액이 가장 큰 활동을 대표 활동으로 선택 | 데이터가 없는 날짜는 계획·잠금 상태로 표시 |
| 공개 금융 프로필 | owner-linked 공개 동의와 선택 필드 | API가 미리보기·공개 projection·철회를 같은 정책으로 적용 | 기본 비공개이며 철회 즉시 검색·추천·캐시에서 제거 |
| 상품·종목·거래 상세 | 명시적으로 공개된 private staging 항목 | API가 읽기 전용 상세로만 제공 | 루틴·퀘스트·XP·포인트·레이드 입력으로 사용하지 않음 |

## 고정 원칙

- 앱 사용자와 합성 페르소나는 `userId + releaseVersion` 기반으로 결정적으로 연결한다.
- 연결된 자신의 페르소나는 비교 탐색 결과에서 제외한다.
- 일반 실행은 최신 데이터 날짜를 사용한다. 고정 2026년 7월·총자산 4,280,000원은
  demo profile 또는 명시적인 Mock fixture 전용이다.
- `metrics_monthly`, `stats`, `stats_history` 등 golden L3는 테스트 비교값이며 화면
  원본이 아니다.
- 모든 계산 응답에는 `calculationVersion`, `dataState`, `lastSyncedAt`을 포함한다.
