# FinMate 합성데이터 도입과 금융 SNS 공개 정책

이 문서는 `gaga-studio/finmate-data`의 합성데이터를 FinMate API로 가져오는 경계와
사용자가 공개한 금융정보를 읽기 전용 SNS에 노출하는 규칙을 정의한다. 원본 번들,
변환 결과, 런타임 데이터와 공개 프로필은 서로 다른 자산이며 같은 저장소나 같은
책임으로 취급하지 않는다.

## 1. 잠긴 원본 릴리스

| 항목 | 값 |
| --- | --- |
| 저장소 | `gaga-studio/finmate-data` |
| 릴리스 | `v1.0.0` |
| L1/L2 번들 커밋 | `63ca3d046eba9ec510e377a28a0083233aefff61` |
| L3 파생 테이블 커밋 | `eab7f87fce65345a22a072b04fd3de59d2a29513` |
| L3 tree SHA-256 | `872c3c7366028f7047957309a03607c31a1a033cb70c4249bd0183adc5182d2b` |
| 릴리스 자산 | `finmate-v3-bundles.tar.zst` |
| SHA-256 | `278226514562ec13ddb69959622bc6342fbe0b2c45e1447fa77422e3f9d3dd58` |
| 데이터 기간 | `2026-01-01`~`2026-07-13` |
| 합성 사용자 | `2,000명` |

- `finmate-data`는 원본 번들, 생성 파이프라인과 검증 결과를 소유한다.
- `finmate-api`는 릴리스 manifest, 허용 목록, importer, 재계산 코드와 seed를 소유한다.
- `finmate-web`은 원본 파일을 읽지 않고 API 응답만 사용한다.
- 압축 또는 추출된 원본 번들은 API Git 저장소에 커밋하지 않는다.
- importer는 다운로드한 자산의 SHA-256과 별도로 L3 31개 parquet의 정렬된 경로·파일
  SHA-256을 합친 tree digest를 검증한다. 번들 또는 L3 출처가 하나라도 다르면 적재를
  시작하지 않는다.
- 변환된 27개 NDJSON의 SHA-256도 lock manifest에 고정한다. 기본 load는 manifest 값만
  믿지 않고 각 파일 바이트와 source-controlled lock을 모두 대조한다.

## 2. 선택적 import 경계

원본 L3의 31개 테이블은 다음처럼 분리한다.

### 런타임 허용 16개

`privacy_settings`, `features`, `cluster_profiles`, `friendships`,
`friend_group_stats`, `feed_events`, `streaks`, `routine_summaries`,
`active_goals`, `goal_history`, `budgets_daily`, `sync_events`,
`retrospectives`, `quiz_log`, `point_ledger`, `quest_log`

각 테이블도 열 허용 목록을 다시 적용한다. 허용 테이블이라는 이유만으로 모든 열을
가져오지 않는다. 안전하지 않은 투자 퀘스트와 그 포인트 이벤트는 변환 중 제거한다.
`friend_group_stats`는 전체 친구 수 `friend_count`와 실제 평균 산정에 참여한
`scored_friend_count`를 구분한다. 잠금 해제 그룹은 세 평균값이 모두 존재하고
`1 ≤ scored_friend_count ≤ friend_count`인 경우에만 적재한다.

### 골든 비교 전용 5개

`balance_monthly`, `budgets_monthly`, `metrics_monthly`, `stats`, `stats_history`

이 결과는 런타임 원본이 아니다. 백엔드가 정제 거래에서 계산한 결과를 검증할 때만
허용 오차 안의 골든 값으로 사용한다. 특히 원본의 `invest_score`를 제품의
`투자 판단력`으로 복사하지 않는다. `balance_monthly`는 절대 자산이 아닌 관찰기간
순변화이며, `budgets_monthly`도 거래에서 다시 계산할 수 있는 파생 요약이다. 다섯
테이블은 별도 `golden_l3/` 산출물로 내보내며 PostgreSQL seed에는 넣지 않는다.

### 제외 10개

`app_sessions`, `bookmarks`, `boss_instances`, `goal_candidates`,
`level_rules`, `point_catalog`, `raid_log`, `reward_boxes`,
`title_catalog`, `titles_earned`

L3 parquet 밖의 `goal_templates.json`도 import하지 않는다. 목표 유형, 허용 범위,
기간과 연결 퀘스트는 API 제품 정책이 소유하며 upstream 메모 변경으로 자동 갱신되지
않는다.

원본 `point_catalog` 대신 아래의 확정형 꾸미기 카탈로그 3개를 사용한다.

| ID | 유형 | 가격 |
| --- | --- | ---: |
| `cosmetic-outfit-mint` | 의상 | 5P |
| `cosmetic-frame-sprout` | 프로필 테두리 | 15P |
| `cosmetic-theme-daylight` | 테마 | 25P |

랜덤 상자, 쿠폰, 현금 전환, 사용자 간 양도와 핵심 리포트 잠금은 없다.

## 3. 변환과 적재

- 금융활동 금액은 음수가 아닌 정수 KRW와 `INFLOW/OUTFLOW` 방향으로 저장한다.
  골든 비교의 월 순변화처럼 부호가 값의 일부인 파생 결과만 signed KRW를 유지한다.
- `0~1` 비율은 `0~10,000` basis point로 변환한다.
- `0~100` 점수는 `0~10,000` 제품 점수로 변환한다.
- 날짜와 시간은 ISO 8601로 통일한다.
- 잠긴 원본의 생활맥락 값은 importer에서 제품 vocabulary로 명시적으로 변환한다.
  `정기`는 `REGULAR`, `1인가구`·`고시원`·`쉐어하우스`는 `RENT`, 부모와의
  동거는 `WITH_FAMILY`로 매핑하며 알 수 없는 값을 임의의 정상 상태로 만들지 않는다.
- 계좌번호, 거래 원문 메모, 상세 직장·위치, 인증 식별자, 원본 파일 참조는
  변환 결과에 포함하지 않는다.
- 모든 seed는 자연키와 `ON CONFLICT` upsert를 사용한다. 동일 릴리스를 다시
  적재해도 행이 늘어나지 않아야 한다.
- runtime L3는 부분 병합이 아니라 release 단위 snapshot이다. 교정 전 payload의 전체
  해시가 자연키에 남지 않도록 기존 snapshot을 트랜잭션 안에서 삭제하고 승인된 16개
  테이블을 모두 다시 넣는다. V12 migration도 기존 L3 snapshot을 먼저 무효화한다.
- 계산 응답은 `calculationVersion`, `dataState`, `lastSyncedAt`을 포함한다.

실행 도구는 [`tools/finmate_data_import`](../../../tools/finmate_data_import/README.md)에
있다. export 결과도 소스 데이터가 아니라 재생성 가능한 임시 산출물로 취급한다.

## 4. 실제 v1.0.0 + L3 `eab7f87` 검증 결과

2026-07-16에 잠긴 번들과 최신 L3를 함께 변환해 다음을 확인했다.

| 변환 결과 | 행 수 |
| --- | ---: |
| 합성 사용자 | 2,000 |
| 금융활동 | 887,002 |
| 금융상품 보유 | 4,000 |
| 투자 보유 | 8,912 |
| 투자 거래 | 16,576 |
| 허용 L3 레코드 | 845,203 |
| 골든 비교 레코드(DB 미적재) | 444,000 |
| 확정형 꾸미기 | 3 |

전체 bootstrap 이후 런타임 projection은 feature 2,000건, behavior 2,000건,
일별 예산 388,000건, 그룹 11건, 승인 루틴 3,939건, 친구 관계 28,040건,
피드 10,000건, 연속기록 27,660건이었다. 소득 규칙성은 `REGULAR 1,120명`과
`IRREGULAR 880명`, 주거 맥락은 `RENT 1,103명`, `WITH_FAMILY 680명`,
`OTHER 217명`으로 정규화됐다.

친구 그룹 2,000개 중 잠금 해제 그룹은 1,832개, 잠금 그룹은 168개다. 잠금 해제
그룹의 누락 평균과 잘못된 `scored_friend_count`는 모두 0건이다. 여윳돈이 0 이하인
141명의 개인 비율 기반 스탯은 의도적으로 미정의 상태를 유지하며, 최신 L3는 이들을
그룹 평균의 분자·분모에서 제외한다.

최신 세그먼트는 `subscription_count`를 군집 입력에서 제외한 12개 피처 기반
k-means 분할이다. 11개 그룹의 크기는 113~273명이고 실루엣 계수는 0.1426이다.
이는 자연적으로 발견된 군집이 아니라 모든 사용자를 최소 100명 이상의 유사 행동
그룹에 배정하기 위한 제품용 분할로 해석한다. 친구 그래프는 형성 시점의 이전 군집
기준으로 동결되어 있어 현재 세그먼트와 친구 형성 기준이 다를 수 있다.

금지 필드와 안전하지 않은 투자 퀘스트는 변환 결과에서 발견되지 않았고, 모든 적재
연산에 upsert가 존재한다. 격리 PostgreSQL에 전체 export를 bootstrap하고 같은
release를 다시 적재했을 때 행 수가 변하지 않았다. 위 숫자는 제품 효과나 실제 고객
규모가 아니라 변환·계약·런타임 연결 검증 범위를 뜻한다.

## 5. 백엔드 계산 책임

백엔드는 정제된 금융활동에서 다음 값을 다시 계산한다.

- 최근 3개월 소득 기준선
- 필수지출과 재량지출
- 여윳돈
- 소비율, 저축률과 투자계좌 순입금률
- 금융 스탯과 목표 진행률

여윳돈이 0 이하이거나 기준 기간이 부족하면 비율을 강제 계산하지 않고
`INSUFFICIENT`를 반환한다. 웹과 코치는 계산하지 않으며 L3 결과를 화면 값으로
직접 노출하지 않는다.

## 6. 항목별 공개 동의

공개 기본값은 모두 비공개다. 사용자는 다음 7개 항목을 독립적으로 선택한다.

1. 총자산과 계정별 자산
2. 수입과 소득 이력
3. 지출과 카테고리 내역
4. 저축액·저축률·저축상품
5. 금융상품명과 보유 상태
6. 투자종목·보유액·비중
7. 매수·매도 기록

저장 전에는 공개 미리보기를 제공한다. 동의 응답에는 선택 항목, 동의 버전과
갱신시각을 포함한다. 다음 필드는 사용자가 요청해도 공개할 수 없다.

- 실명과 원천 사용자 ID
- 계좌번호
- 거래 원문 메모
- 상세 직장과 상세 위치
- 인증 식별자

철회는 즉시 적용한다. 공개 프로필, 추천 카드와 프로세스 내 캐시에서 해당 사용자를
제거하며, 이미 철회된 프로필을 fallback 데이터로 다시 보여주지 않는다. 공개
프로필에 소유 사용자가 연결된 경우 동의 변경과 철회는 같은 트랜잭션에서 프로필
노출 상태와 선택 필드에도 투영한다.

## 7. 공개 프로필과 안전한 따라하기

`PublicFinancialProfile`은 동의된 항목만 포함한다. 상품명, 종목, 보유액과 거래
기록이 공개됐더라도 모두 정보 열람 전용이다.

`빌드 따라하기`가 변환할 수 있는 것은 다음 루틴뿐이다.

- 저축 빈도와 먼저 저축하기
- 예산 확인과 범위 유지
- 구독 점검
- 자동저축 유지
- 위험성향 확인, 분산 점검과 금융 학습

상품 가입, 종목 매수, 매매 시점, 투자금 증액은 루틴·퀘스트·XP·포인트·레이드
입력이 될 수 없다. 공개 정보와 행동 추천은 API 모델과 화면에서도 분리한다.

## 8. XP, 포인트와 소셜

- XP는 캐릭터 레벨과 퀘스트 성장에만 사용한다.
- 내부 포인트는 확정형 꾸미기 구매에만 사용한다.
- 투자금, 거래량, 수익률과 상품 가입에는 XP나 포인트를 지급하지 않는다.
- 친구 현황, 금액 없는 피드와 연속기록은 합성 읽기 전용이다.
- 친구 추가, 팔로우, 찜하기와 소셜 쓰기 API는 MVP에 없다.

## 9. 시연 데이터 분리

원본 데이터 기간은 2026-07-13에 끝난다. 7월부터 다음 해 1월까지 진행하는 90초
시연은 별도의 결정적 fixture다. 이 fixture는 합성 demo 사용자와 `demo` 환경에서만
활성화하며 일반 사용자 데이터, importer 검증 수치나 연구 결과로 표현하지 않는다.

`demo` 환경의 새 데이터베이스에 런타임 projection이 전혀 없으면 비교 탐색과 기록
E2E를 위한 최소 합성 fixture를 멱등적으로 생성한다. 전체 2,000명 projection이 한 건이라도
존재하면 이 fixture는 생성되지 않는다. 따라서 이 최소 fixture는 로컬 시연과 계약 검증만
위한 것이며 위의 전체 적재 건수나 제품 데이터로 합산하지 않는다.

## 10. 수용 기준

- manifest의 번들 커밋, 아카이브 SHA, L3 커밋, L3 tree digest 또는 27개 export 파일
  checksum이 다르면 import가 중단된다. 구형 단일 `sourceCommit` manifest도 허용하지
  않는다.
- 허용 목록 밖 테이블과 금지 필드는 API DB에 적재되지 않는다.
- 동일 export를 반복 적재해도 자연키별 행 수가 변하지 않는다.
- 백엔드 계산은 골든 L3와 허용 오차 안에서 일치한다.
- 미동의 필드는 공개 프로필·추천·로그에 나타나지 않는다.
- 철회한 사용자는 공개 프로필과 추천 결과에서 즉시 사라진다.
- 공개 상품·종목·거래 열람은 루틴, 퀘스트, 보상과 진행률에 영향을 주지 않는다.
- 친구·피드·연속기록에는 쓰기 계약이 없다.
- 쿠폰, 랜덤 상자와 투자 실행 퀘스트가 seed와 API 응답에 없다.
- 잠금 해제 친구 그룹은 세 평균값과 실제 산정 인원을 모두 가지며, 화면은 전체 친구
  수와 실제 산정 인원을 같은 의미로 표시하지 않는다.
