## 0. 발표에서 단 하나만 기억시킬 문장

> FinMate는 나와 비슷한 익명 모험가의 금융 루틴을 내 상황에 맞게 가져와,
> 실제 금융행동을 퀘스트와 레이드로 이어가는 금융 습관 앱입니다.

발표의 모든 장면은 아래 인과관계를 설명해야 한다.

```text
내 목표 확정
→ 비슷한 익명 모험가 발견
→ 유지한 루틴 확인
→ 내 기준선으로 실행 강도 계산
→ 오늘의 퀘스트
→ 금융데이터에서 행동 확인
→ 스탯·목표 진행률·레이드·기록 갱신
```

하나 파워온 공개 페이지의 `실현가능성 30%·사업성 30%·참신성 30%·자료완결성
10%`는 **서류심사 기준**이다. 별도 최종 심사표가 공개되지 않았으므로 이를 최종
배점이라고 부르지 않고, 발표 점검 관점으로만 사용한다.

## 1. 기존 발표에서 바꿀 것

### 1.1 객관적인 문제 진단

| 기존 문제 | 왜 약한가 | 새 구성에서의 처리 |
| --- | --- | --- |
| FOMO와 자극을 문제 해결의 핵심으로 사용 | 사회적 압박을 다시 강화하며 서비스 안전 원칙과 충돌한다. | `비슷한 출발점의 루틴 발견`과 `작은 행동 선택`으로 교체한다. |
| 40명 편의표본을 핵심 시장 근거처럼 제시 | 대표성이 없고 효과 검증도 아니다. | 본문에서 빼고 `초기 문제 탐색`으로만 백업에 둔다. |
| 생일펀드·친구·포인트·프로필 등 기능을 순서대로 나열 | 제품이 해결하는 한 가지 문제가 기억되지 않는다. | `모험가→루틴→퀘스트→검증→레이드` 한 경로만 본문에 둔다. |

| WALLY 한 캐릭터의 체형으로 모든 금융 상태 표현 | 현재 곰·물개·토끼·새 리포트 체계와 불일치한다. | 네 동물은 6번 슬라이드에서 데이터 영역을 설명할 때만 사용한다. |
| 합성데이터·세그멘테이션·AI 수치를 기술 성과로 길게 나열 | 사용자 가치와 연결되지 않고 현재 vNext 구현 상태를 설명하지 못한다. | 계층별 검증 결과와 실제 API 통합의 남은 경계를 8번 한 장에 정리한다. |
| 하나 연계를 승인된 사업처럼 표현 | 하나와의 실제 도입 합의나 준법 검토가 없다. | 하나 합 기반의 `제안`과 100명 파일럿 가설로 명확히 낮춘다. |

## 2. 본문 10장

### 1장 · 남의 잔액을 따라하지 않고, 내게 맞는 루틴을 가져옵니다

- **시간:** 0:00~0:15
- **역할:** 서비스의 차이를 한 문장으로 기억시킨다.
- **근거 라벨:** `제품계약`

#### 화면에 넣을 텍스트

```text
남의 잔액을 따라하지 않고,
내게 맞는 루틴을 가져옵니다

비슷한 익명 모험가
→ 내 기준선으로 가공
→ 오늘의 퀘스트
→ 검증된 금융 변화
→ 레이드 성장

FinMate · 금융 습관 RPG
```

#### 구성

- 앱 대표 화면은 하나만 크게 사용한다.
- 화면 옆에는 다섯 단계 흐름만 배치한다.
- 팀명·행사명은 하단에 작게 두고 기능 목록은 넣지 않는다.
- 4인 파티, 공동 보스, 공개 순위 이미지는 사용하지 않는다.

#### 발표 대본

> FinMate는 남의 잔액을 보여주고 경쟁시키는 앱이 아닙니다. 비슷한 출발점의
> 익명 모험가가 유지한 루틴을 내 상황에 맞게 바꾸고, 실제 금융행동이 확인될
> 때만 레이드가 진행되는 금융 습관 앱입니다.

---

### 2장 · 20대의 금융 공백은 점검과 목표 설정 행동에서도 보입니다

- **시간:** 0:15~0:45
- **역할:** 해결할 문제를 공식 통계 한 장으로 좁힌다.
- **근거 라벨:** `공식통계`

#### 화면에 넣을 텍스트

```text
20대의 금융 공백은
점검과 목표 설정 행동에서도 보입니다

재무상황 정기 점검
20대 33.2점  |  전체 43.4점

장기 재무목표 설정
20대 36.1점  |  전체 42.5점

제품 가설
더 많은 정보보다, 내 상태를 점검하고
다음 행동을 고르는 경험이 필요하다.
```

하단 출처:

```text
한국은행·금융감독원, 「2024 전국민 금융이해력 조사」,
만 18~79세 2,400명, 2025.04.29.
```

#### 구성

- 수치 카드는 두 개만 사용한다.
- 20대와 전체를 같은 축에서 비교한다.
- `정보 부족이 원인`이라고 쓰지 않고 결론 앞에 `제품 가설`을 붙인다.

#### 발표 대본

> 2024년 한국은행과 금융감독원이 성인 2,400명을 조사한 결과, 20대의 재무상황
> 점검은 33.2점, 장기 목표 설정은 36.1점으로 전체보다 낮았습니다. 이 조사만으로
> 원인을 단정할 수는 없습니다. 다만 금융지식을 전달한 다음, 내 상태를 점검하고
> 무엇부터 할지 고르는 행동의 공백이 있다는 제품 가설을 세울 수 있었습니다.

#### 말하면 안 되는 표현

- `20대는 금융을 모른다`
- `정보는 충분한데 의지가 부족하다`
- `FinMate가 이 문제를 해결했다고 입증했다`

---

### 3장 · 외부 연구의 가능성과 위험을, 네 가지 설계 가설로 번역했습니다

- **시간:** 0:45~1:20
- **역할:** 연구 결과를 기능 자랑이 아니라 설계 원칙으로 전환한다.
- **근거 라벨:** `외부연구`

#### 화면에 넣을 텍스트

```text
외부 연구의 가능성과 위험을
네 가지 설계 가설로 번역했습니다

연구 신호 → FinMate 설계 가설

목표 설정과 저축의 연결
사용자가 목표를 직접 확인하고 확정한다

게임형 교육의 이해도 개선
캐릭터와 레이드는 금융상태를 읽는 표현이다

그룹 개입의 행동 가능성
유사한 출발점에서 유지된 루틴만 보여준다

상향 비교·거래 게임화의 위험
정확값은 기본 비공개·선택 공개, 순위·거래 보상은 없앤다

외부 연구는 설계 근거이며, FinMate 효과는 별도 검증 대상
```

하단에 숫자는 세 개까지만 표시한다.

```text
게임형 금융교육 2,220명(4개국 학생)·금융이해력 +0.313SD
그룹저축 2,687명(칠레 마이크로크레디트 이용자)·결합 개입 후 예금 횟수 3.7배
거래앱 9,000명 이상(영국 온라인 실험)·일부 게임화가 거래·위험 행동 증가
```

#### 발표 대본

> 목표 설정은 한 핀테크 연구 환경에서 저축률 증가와 연결됐고, 게임형 금융교육
> 실험은 학생의 금융이해력을 0.313 표준편차 높였습니다. 그룹저축 실험에서는 목표,
> 모니터링, 비금전 보상을 묶은 개입 뒤 예금 횟수가 3.7배였습니다. 반대로 높은
> 또래 수치와 거래앱 게임화는 낙담이나 위험 행동을 키울 수 있었습니다. 이 결과가
> FinMate의 효과를 증명하지는 않습니다. 저희는 이를 사용자가 확정한 목표,
> 유사한 출발점의 루틴, 정확값의 항목별 선택 공개, 순위·거래 보상 금지라는
> 설계 가설로 번역했습니다.

#### 근거 한계

- 다섯 근거의 대상·국가·개입이 서로 다르다.
- `3.7배`는 목표 설정, 집단 모니터링, 비금전 보상이 결합된 결과다.
- 외부연구는 FinMate의 효과 검증이 아니라 설계 근거다.

### 4장 · FinMate의 차이는 추천이 아니라 루틴을 내 수치로 바꾸는 데 있습니다

- **시간:** 1:20~1:45
- **역할:** 참신성을 실제 계산 예시로 설명한다.
- **근거 라벨:** `제품계약`·`시연fixture`

#### 화면에 넣을 텍스트

```text
FinMate의 차이는 추천이 아니라
루틴을 내 수치로 바꾸는 데 있습니다

내 목표
유럽여행경비 200만원 → 500만원
2027년 1월까지 300만원 필요

익명 모험가에게서 발견
월급날 먼저 저축 · 180일 유지

내 기준선으로 가공
남은 6개월 · 월 50만원 추천

생성된 서브퀘스트
매월 50만원 자동저축 설정·유지하기
```

하단 원칙:

```text
상대 금액 복사 X · 목표 변경 X · 코드 계산 O · 사용자 확정 O
```

#### 구성

- `목표 → 루틴 → 개인화 후보 → 퀘스트` 네 칸을 왼쪽에서 오른쪽으로 연결한다.
- `300만원 ÷ 6개월 = 월 50만원` 계산은 한 번만 보여준다.
- 실제 제품에서는 기준선·안전 범위 검사를 거친다는 설명을 하단에 둔다.

#### 발표 대본

> 사용자의 목표는 유럽여행경비 500만원입니다. 메이트에서 발견하는 것은 다른
> 사람의 목표액이 아니라, 월급날 먼저 저축을 180일 유지한 루틴입니다. FinMate는
> 남은 300만원과 6개월, 내 기준선을 코드로 확인해 월 50만원 실행안을 만들고,
> 사용자가 확정하면 퀘스트로 연결합니다. 루틴을 가져와도 내 목표는 바뀌지 않습니다.

### 5장 · 90초 시연

- **시간:** 1:45~3:15
- **역할:** 설명한 인과관계를 한 번에 체감시킨다.
- **근거 라벨:** `시연fixture`

#### 화면에 넣을 텍스트

영상 외에는 다음 라벨만 유지한다.

```text
합성데이터 기반 결정적 프로토타입
실제 마이데이터·상품가입 미연동
```

#### 영상 순서

| 시간 | 장면 | 반드시 보여줄 상태 |
| ---: | --- | --- |
| 0~13초 | 온보딩·합성 마이데이터·기준선 | 아직 활성 목표 없음 |
| 13~19초 | 유럽여행경비 목표 확정 | 200만원→500만원, 2027년 1월 |
| 19~29초 | 홈 레이드·네 동물 리포트 | 서로 다른 네 리포트 |

#### 발표 중 말할 문장

> 유럽여행 목표를 정한 사용자가 자신과 비슷한 모험가의 루틴을 찾습니다.

루틴 적용 장면:

> 복사하는 것은 금액이 아니라, 검증된 실행 방식입니다.

기록·완료 장면:

> 퀘스트를 눌렀기 때문이 아니라, 확인된 저축 데이터가 쌓여 레이드가 진행됩니다.

그 외에는 영상에 집중하고 화면 기능을 계속 읽어주지 않는다.

### 6장 · 게임이 돈을 만들지 않고, 확인된 돈의 변화가 게임을 움직입니다

- **시간:** 3:15~3:50
- **역할:** 금융 앱으로서의 신뢰성과 계산 책임을 설명한다.
- **근거 라벨:** `제품계약`

#### 화면에 넣을 텍스트

```text
게임이 돈을 만들지 않고,
확인된 돈의 변화가 게임을 움직입니다

퀘스트 완료
→ 퀘스트 XP·꾸미기 포인트·기록만 증가

금융데이터 동기화
→ 금융 스탯·목표 진행률·레이드 재계산

하나 상품 정보 열람
→ 정보만 제공, 성장·보상 변화 없음
```

작은 범례:

```text
곰 소비 방어력 · 물개 저축 HP
토끼 투자 판단력 · 새 퀘스트 XP
```

#### 발표 대본

> FinMate에는 서로 다른 두 성장선이 있습니다. 퀘스트를 완료하면 새의 XP, 확정형
> 꾸미기에만 쓰는 포인트와 행동 기록이 늘어납니다. 곰, 물개, 토끼의 금융 스탯과 목표 진행률·레이드는 새로운 금융
> 데이터가 확인된 뒤 서버가 재계산할 때만 바뀝니다. 상품 정보는 이 흐름과 완전히
> 분리해, 보기만 해도 보상을 받거나 가입을 유도하는 구조를 만들지 않았습니다.

---

### 7장 · 사용자는 설명 없이도 목표와 루틴의 차이를 이해했는가

- **시간:** 3:50~4:25
- **역할:** 제품을 만든 팀의 주장 대신 사용자의 실제 이해를 보여준다.
- **근거 라벨:** `내부검증`

실제 테스트 전에는 본문 장으로 확정하지 않는다. 결과는
[`사용성 검증 양식`](usability-test-template.md)에 따라 기록한다.

#### 결과가 있을 때 넣을 텍스트

```text
사용자는 설명 없이도
목표와 루틴의 차이를 이해했는가

핵심 과제 완료           [X]/6명
목표와 루틴 구분         [Y]/6명
금융데이터→레이드 이해   [Z]/6명
실행 의향 중앙값         [N]/5점

발견
[관찰된 가장 큰 문제 한 문장]

수정
[화면 또는 카피 수정 한 문장]
```

#### 발표 대본 템플릿

> 금융 초보 청년 6명에게 설명 없이 핵심 흐름을 수행하게 했습니다. [X]명이 전체
> 과제를 완료했고, [Y]명이 목표와 가져오는 루틴을 구분했습니다. 가장 크게 막힌
> 지점은 [문제]였고, 이를 [수정]으로 바꿨습니다. 이는 효과성 검증이 아니라
> 발표 전 실시한 초기 사용성 검증입니다.

#### 결과가 없을 때 사용할 대체 7장

사용성 결과가 없더라도 10장·6분 50초 형식을 유지한다. 결과 자리에는 성과를
만들어 넣지 않고 아래 검증 질문을 같은 35초 슬롯에 배치한다.

- **대체 제목:** 효과를 주장하기 전에 세 가지 이해부터 검증하겠습니다.
- **대체 역할:** 아직 검증하지 않은 가정과 판정 방식을 정직하게 공개한다.
- **대체 근거 라벨:** `후속계획`
- **하단 출처:** `FinMate 초기 사용성 검증 계획 · 아직 결과 없음`

```text
효과를 주장하기 전에
세 가지 이해부터 검증하겠습니다

1. 목표와 가져오는 루틴을 구분하는가
2. 퀘스트 클릭이 아닌 금융데이터가 레이드를 움직인다고 이해하는가
3. 익명 모험가 비교가 압박보다 실행 도움으로 느껴지는가

대상  금융 초보 청년 6명
판정  과제 완료 N/6 · 오답 원문 · 수정 전후

아직 결과 없음 · 발표 후속 검증
```

대체 발표 대본:

> 아직 사용자 결과는 만들지 않았습니다. 대신 제품의 핵심 가정 세 가지를 먼저
> 검증하겠습니다. 목표와 루틴을 구분하는지, 클릭이 아니라 금융데이터가 레이드를
> 움직인다고 이해하는지, 비교가 압박보다 실행 도움으로 느껴지는지를 금융 초보
> 청년 6명에게 설명 없이 확인하겠습니다. 결과는 성공률뿐 아니라 오답 원문과
> 수정 전후까지 남기겠습니다.

### 8장 · 핵심 흐름은 계층별로 검증했고, 실제 API 통합은 아직 남았습니다

- **시간:** 4:25~5:10
- **역할:** 현재 구현과 후속 작업의 경계를 정확히 보여준다.
- **근거 라벨:** `현재구현`·`후속계획`

#### 화면에 넣을 텍스트

```text
핵심 흐름은 계층별로 검증했고,
실제 API 통합은 아직 남았습니다

2026.07.14 검증
API 테스트 105개
importer 테스트 22개
합성 금융활동 887,002건 선택 변환

확인한 통합 경계
OpenAPI 44개 operation 계약 검증
최종 웹·실제 API E2E 미검증

다음
7월 14일 디자인 인수
OpenAPI 클라이언트·화면 정렬

```

위 수치는 2026년 7월 14일 기준이다. 발표 48시간 전에 같은 명령을 다시 실행해
값과 통합 상태를 갱신한다. 실제 API E2E가 통과하지 않으면 미통과 문구를 유지한다.

#### 발표 대본

> 현재 API 테스트 105개와 importer 테스트 22개가 통과했고, 잠긴 합성데이터의
> 금융활동 88만 7천여 건을 허용 필드로 변환했습니다. 정확값 공개 동의와 철회,
> 읽기 전용 소셜 경계도 API에서 확인했습니다. 다만 최종 웹과 실제 API E2E는
> 디자인 인수 뒤 다시 연결해야 합니다. 따라서 지금은 데이터·API 경계를 검증한
> 상태이지 신규 경험 전체가 통합됐다고 말하지 않겠습니다.

#### 반드시 표시할 경계

- 실제 마이데이터: 미연동
- 실시간 생성형 AI: MVP 미사용
- 하나 상품 가입: 미제공
- 확장 OpenAPI 전체: 런타임 구현 완료로 주장하지 않음
- 실제 API E2E: 최종 웹 생성 클라이언트 정렬 전까지 미검증

### 9장 · 하나 합의 자산관리 기반을 매일 실행하고 돌아오는 경험으로 확장합니다

- **시간:** 5:10~6:10
- **역할:** 하나와 사용자 양쪽에 왜 필요한지 설명한다.
- **근거 라벨:** `공식서비스`·`제안`

#### 화면에 넣을 텍스트

```text
하나 합의 자산관리 기반을
매일 실행하고 돌아오는 경험으로 확장합니다

하나 합
마이데이터 기반 자산관리

FinMate 제안
익명 루틴 발견
→ 내 퀘스트
→ 검증된 행동 기록
→ 관련 상품 정보

100명 · 4주 초기 파일럿 제안

핵심 KPI
목표 확정률 · 루틴 적용률
검증된 첫 행동 · D7 재방문 · 4주 유지율
```

가드레일은 하단에 작게 둔다.

```text
비교 압박 · 데이터 불일치 · 개인정보 불안 추적
투자 유도 문구 0건
```

#### 발표 대본

> 하나원큐는 하나 합을 통해 마이데이터 기반 자산관리 경험을 제공하고 있습니다.
> FinMate는 그 진단과 조회 이후에 사용자가 무엇을 할지 고르고 다시 돌아오는
> 청년 금융습관 모듈을 제안합니다. 익명 루틴을 발견하고, 내 퀘스트로 바꾸고,
> 검증된 행동을 기록합니다. 관련 상품은 별도 정보 카드로만 연결합니다. 첫 검증은
> 100명, 4주로 제안하며 가입률이 아니라 검증된 첫 행동과 4주 루틴 유지를
> 핵심 지표로 보겠습니다.

#### 표현 제한

- `하나와 연동했다`, `하나가 도입한다`, `하나 합에 또래 비교가 있다`고 말하지 않는다.
- 100명·4주는 효과를 입증하는 실험이 아니라 초기 파일럿 제안이다.
- 상품 가입률·매출 증가를 보장하지 않는다.

## 4. 발표 제작 규칙

- 제목은 화면명이 아니라 해당 장에서 증명할 결론으로 쓴다.
- 한 장에 핵심 주장 1개, 주요 숫자 3개 이하, 그래프 1개 이하만 둔다.
- 본문 한글은 발표 화면에서 읽히는 최소 크기를 유지하고 긴 문장은 발표자가 말한다.
- `공식통계·외부연구·현재구현·내부검증·제안`을 같은 성과처럼 섞지 않는다.
- 외부 연구 숫자 옆에는 대상·맥락·한계를 함께 적는다.
- 소규모 사용성 결과는 백분율이 아니라 `N/6명`으로 표기한다.
- 출처는 슬라이드 하단에 기관·제목·연도와 짧은 URL 또는 각주 번호로 적는다.
- `업계 최초`, `효과 입증`, `AI가 계산`, `하나 도입 확정` 표현을 사용하지 않는다.
- 이전 방 기반 콘셉트, 이전 단일 캐릭터명, 공동 파티 전투, 공개 순위,
  현금성 포인트, 구식 공격형 투자 스탯명, 수익률 보상을 본문과 백업에서 제거한다.

## 5. 발표 48시간 전 동결 체크리스트

- [ ] API·웹 테스트, lint, build를 다시 실행하고 8장의 숫자를 갱신했다.
- [ ] 실제 구현, 결정적 시연, 후속 제안을 서로 다른 라벨로 표시했다.
- [ ] 7장의 결과가 원자료와 일치하거나, 결과가 없어 `후속계획` 대체 7장을 사용했다.
- [ ] 영상이 90초±0.5초이고 네트워크 없이 재생된다.
- [ ] 시연에서 퀘스트 수락 직후 금융 스탯·레이드가 오르지 않는다.
- [ ] 상품 정보 열람이 XP·스탯·레이드에 영향을 주지 않는다.
- [ ] 슬라이드의 모든 숫자가 [`주장·출처표`](claims-and-sources.md)에 연결된다.
- [ ] 5회 리허설 모두 영상 포함 6분 50초 이내다.
- [ ] 최종 심사 기준이 별도로 배포됐는지 확인하고, 없으면 서류 배점을 최종 배점으로 부르지 않는다.
