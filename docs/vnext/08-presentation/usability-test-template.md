# FinMate 6인 초기 사용성 검증 양식 v1

> 목적: FinMate의 효과를 증명하는 실험이 아니라, 설명 없이도 핵심 흐름과
> 인과관계를 이해하는지 확인하는 형성적 사용성 테스트다.  
> 대상 화면: 목표 확정 → 홈 레이드 → 퀘스트 → 메이트 → 루틴 적용 → 기록

## 1. 이번 테스트가 답할 질문

1. 사용자는 `목표`와 메이트에게서 가져오는 `루틴`을 구분하는가?
2. 보스를 누른 뒤 현재 목표와 연결된 퀘스트를 찾고 수락할 수 있는가?
3. 추천 모험가의 금액이 아니라 실행 방식을 가져온다는 점을 이해하는가?
4. 퀘스트 클릭이 아니라 검증된 금융데이터가 레이드를 움직인다는 점을 이해하는가?
5. 일별 발판에서 어떤 데이터가 성장에 반영됐는지 찾을 수 있는가?
6. 비교 압박, 개인정보 노출, 투자 유도처럼 불안하게 느끼는 지점은 무엇인가?

이번 테스트로 답할 수 없는 질문:

- 실제 저축액이나 금융행동이 장기간 개선되는가
- 4주 유지율이나 D7 재방문율이 개선되는가
- 청년 전체가 제품을 선호하는가
- 실제 마이데이터·상품 연결이 안정적인가

## 2. 참여자와 모집

### 필수 조건

- 만 19~34세
- FinMate 팀원이 아니며 제품 기획을 사전에 듣지 않음
- 본인을 금융 초보 또는 금융관리를 이제 시작하는 단계라고 인식
- 한국어 모바일 앱을 일상적으로 사용

## 3. 진행 원칙

- 1인당 20~25분, 진행자 1명과 관찰자 1명을 권장한다.
- 진행자는 기능을 설명하지 않고 과제 목표만 읽는다.
- 참여자가 20초 이상 멈추면 먼저 `지금 무엇을 찾고 계세요?`라고 묻는다.
- 직접 위치를 알려준 순간부터 해당 과제는 `도움 후 성공`으로 기록한다.
- 참여자의 말과 관찰자의 해석을 분리해 적는다.
- 테스트 도중 화면을 수정하지 않고 모든 6인 세션 뒤에 공통 문제를 정리한다.

### 시작 안내문

> 지금 보실 화면은 합성 금융데이터로 만든 초기 프로토타입입니다. 사용자를
> 테스트하는 것이 아니라 화면을 테스트합니다. 모르는 부분은 추측하며 진행해
> 주세요. 진행 중에는 제가 기능을 설명하지 않겠습니다. 생각하는 내용을 소리 내어
> 말해주시면 도움이 됩니다. 언제든 중단할 수 있습니다.

## 4. 과제 시나리오

### T1. 목표 확정

진행자가 읽을 문장:

> 현재 200만원이 있고, 2027년 1월까지 유럽여행경비 500만원을 모으고 싶습니다.
> 이 목표를 앱에 확정해 주세요.

성공 조건:

- `자금 모으기`를 선택한다.
- 목표 이름·현재값·목표값·목표 월을 검토한다.
- 명시적인 확정 행동을 한다.

관찰 포인트:

- 기준선 진단과 목표 설정을 혼동하는가
- `일단 탐색하기`와 목표 확정의 차이를 이해하는가
- 현재값·목표값의 방향을 바꾸어 입력하는가

### T2. 보스에서 퀘스트 수락

진행자가 읽을 문장:

> 목표를 위해 지금 할 수 있는 첫 행동을 찾아 수락해 주세요.

성공 조건:

- 홈의 보스를 통해 퀘스트 맥락으로 이동한다.
- 진행 중 퀘스트가 0개임을 이해한다.
- `이번 달 저축 가능액 확인하기` 추천 퀘스트를 수락한다.

관찰 포인트:

- 보스를 전투 조작 대상으로만 인식하는가
- 퀘스트 수락 직후 레이드가 올라갈 것으로 기대하는가
- 추천 이유·검증 방식을 찾는가

### T3. 익명 모험가의 루틴 찾기

진행자가 읽을 문장:

> 나와 비슷한 조건에서 여행자금 목표를 달성한 사람이 어떤 습관을 유지했는지
> 찾아보세요.

성공 조건:

- 메이트에서 친구 현황과 그룹을 지나 비교 탐색으로 이동한다.
- 유사그룹과 익명 추천 모험가의 차이를 이해한다.
- 모험가 상세 또는 리포트에서 유지한 루틴을 찾는다.

관찰 포인트:

- 친구·메이트 찾기·비교 탐색의 역할을 구분하는가
- 익명 카드의 수치를 순위나 실제 자산으로 오해하는가
- 왜 이 모험가가 추천됐는지 찾을 수 있는가

### T4. 루틴 적용

진행자가 읽을 문장:

> 이 모험가의 방식 중 내 여행자금 목표에 맞는 행동 하나를 가져와 보세요.

성공 조건:

- `월급날 먼저 저축`이 루틴임을 확인한다.
- 내 기준선에서 계산된 `월 50만원` 추천안을 확인한다.
- 추천 서브퀘스트를 확정한다.

관찰 포인트:

- 상대의 목표나 금액을 그대로 복사한다고 생각하는가
- 내 목표가 모험가의 목표로 바뀐다고 생각하는가
- 추천 강도와 사용자 확정 단계를 인지하는가

### T5. 기록에서 반영 근거 확인

진행자가 읽을 문장:

> 시간이 지난 뒤 목표가 진행된 이유를 기록 화면에서 확인해 주세요.

성공 조건:

- 기록 탭의 월·날짜 발판을 탐색한다.
- 월급날 자동저축 활동을 찾는다.
- 날짜 발판을 눌러 일일 상세에서 저축과 데이터 반영을 확인한다.

관찰 포인트:

- 발판의 대표 활동과 전체 일일 활동을 혼동하는가
- 퀘스트 완료와 금융데이터 반영을 같은 것으로 보는가
- 마지막 동기화·데이터 상태를 찾는가

## 5. 사후 이해 질문

질문은 선택지를 먼저 보여주지 않고 열린 질문으로 묻는다. 답변을 그대로 적은 뒤
아래 기준으로 판정한다.

### Q1. 목표와 루틴

> 이 앱에서 `유럽여행경비 500만원`과 `월급날 먼저 저축`은 각각 무엇인가요?

정답 판정:

- 목표는 달성하려는 중기 결과다.
- 루틴은 목표를 위해 가져온 반복 실행 방식이다.
- 두 요소 모두 언급해야 `이해`로 기록한다.

### Q2. 레이드 진행 원인

> 레이드의 진행률은 무엇이 바뀔 때 올라가나요?

정답 판정:

- 검증·동기화된 금융데이터 또는 실제 저축 변화를 언급한다.
- 퀘스트 클릭·시간 경과·전투 승리만 답하면 `미이해`다.

### Q3. 모험가에게서 가져온 것

> 방금 추천 모험가에게서 무엇을 가져왔나요?

정답 판정:

- 루틴·실행 방식·습관 중 하나를 말한다.
- 상대의 정확 금액·자산·목표를 복사했다고 답하면 `미이해`다.

### Q4. 실행 의향

> 이런 방식으로 제안된 다음 행동을 실제로 한 번 실행해 볼 의향이 있나요?

`1 전혀 없다 · 2 낮다 · 3 보통 · 4 있다 · 5 매우 있다`

보조 질문:

- 그렇게 답한 가장 큰 이유는 무엇인가요?
- 실행 전에 꼭 확인하고 싶은 정보는 무엇인가요?

### Q5. 비교·개인정보 불안

> 다른 익명 사용자의 루틴을 보는 동안 불편하거나 비교 압박을 느낀 부분이 있었나요?

`1 전혀 없음 · 2 낮음 · 3 보통 · 4 높음 · 5 매우 높음`

보조 질문:

- 공개되면 안 된다고 느낀 정보는 무엇인가요?
- 투자나 상품 가입을 권유받는 느낌이 있었나요?

## 6. 과제별 기록표

성공 상태는 다음 셋만 사용한다.

- `독립 성공`: 도움 없이 완료
- `도움 후 성공`: 진행자의 위치·기능 설명 뒤 완료
- `실패`: 도움을 받아도 완료하지 못함 또는 잘못된 결과 확정

### 세션별 관찰 기록

| 시각 | 화면 | 참여자의 행동·직접 발화 | 진행자 개입 | 해석 후보 |

`해석 후보`는 관찰과 분리한다. 예를 들어 `루틴 버튼을 18초 찾지 못함`은 관찰이고
`버튼 위계가 약함`은 해석 후보다.

## 7. 사전 성공 기준과 판정

| 지표 | 사전 기준 | 집계 방법 |
| --- | ---: | --- |
| 핵심 과제 완료 | 5/6명 이상 | T1~T5를 모두 독립 성공한 사람 수 |
| 목표·루틴 구분 | 5/6명 이상 | Q1 열린 답변 판정 |
| 금융데이터→레이드 이해 | 5/6명 이상 | Q2 열린 답변 판정 |
| 실행 의향 | 중앙값 4/5 이상 | Q4 개별 응답의 중앙값 |

기준은 테스트 전에 고정한다. 미달 결과를 `대체로 성공`처럼 바꾸지 않는다. 불안 점수는
성공 여부와 별도로 보고하며, 한 명이라도 동의 없는 정확값·영구 금지 개인정보·
투자 유도를 심각한 문제로 지적하면 원문과 수정 여부를 기록한다.

## 8. 문제 우선순위와 수정 기록

문제는 빈도만으로 정하지 않고 `과제 차단`, `금융 인과 오해`, `안전·신뢰 위험`을
우선한다.

| 문제 ID | 관찰 근거 | 영향 인원 | 심각도 | 원인 가설 | 수정 | 재확인 결과 |
| --- | --- | ---: | --- | --- | --- | --- |
| U01 |  |  | 차단/높음/중간/낮음 |  |  |  |

발표 7장에는 문제를 많이 나열하지 않는다. 가장 중요한 문제 1개와 실제 반영한 수정
1개만 보여준다. 수정하지 못했다면 `수정 예정`이 아니라 현재 한계로 말한다.

## 9. 7번 슬라이드 결과 작성 규칙

### 결과가 있는 경우

```text
초기 사용성 검증 · 금융 초보 청년 6명

핵심 과제 완료           X/6명
목표와 루틴 구분         Y/6명
금융데이터→레이드 이해   Z/6명
실행 의향 중앙값         N/5점

발견  [관찰 사실 한 문장]
수정  [실제 반영한 변경 한 문장]
```

- 백분율로 환산하지 않는다.
- 성공 목표 `5/6`을 실제 결과처럼 쓰지 않는다.
- 참여자의 긍정 발화만 선별하지 않는다.
- 대표 인용은 20단어 이내로 익명 처리하며 원자료와 일치해야 한다.
- `사용성`, `이해`, `실행 의향`만 말하고 금융 효과를 주장하지 않는다.

### 발표 전에 결과가 없는 경우

- 7번 슬라이드를 삭제해 10장 구성을 깨지 않는다.
- 본문 텍스트 설계서의 `결과가 없을 때 사용할 대체 7장`을 사용한다.
- 모든 결과 칸 대신 검증 질문·대상·판정 방식과 `아직 결과 없음`을 표시한다.
- 성공 기준을 실제 결과처럼 표시하지 않는다.

## 10. 종료 체크리스트

- [ ] 모든 참여자가 팀 외부 인원이며 사전 제품 설명을 듣지 않았다.
- [ ] 합성데이터 프로토타입임을 알렸고 실제 금융정보를 받지 않았다.
- [ ] 모든 세션에서 같은 과제 문구와 같은 프로토타입 버전을 사용했다.
- [ ] 도움을 준 과제를 독립 성공으로 기록하지 않았다.
- [ ] 열린 질문의 원문 답변을 보존한 뒤 이해 여부를 판정했다.
- [ ] 집계값을 다른 팀원이 원자료에서 재현할 수 있다.
- [ ] 발견 문제와 수정 내용이 화면 버전 또는 커밋으로 연결된다.
- [ ] 발표용 숫자가 [`주장·출처표`](claims-and-sources.md)의 내부 수치 동결표와 일치한다.
