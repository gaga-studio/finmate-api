# 위험 레지스터

## 1. 평가 기준

가능성과 영향은 1~5점이며 `고유 점수 = 가능성 × 영향`이다. 15~25는 매우 높음, 8~14는 높음, 4~7은 보통, 1~3은 낮음이다. 완화 후 잔여 점수도 같은 방식으로 평가한다.

- **위험 소유자**는 예방 통제와 지표를 주간 검토한다.
- **발동 조건**이 발생하면 대응 소유자가 즉시 계획을 실행하고 출시 판단자에게 보고한다.
- 개인정보·금융 계산·AI 수치·투자 유도 관련 S1은 점수와 무관하게 출시 중지 대상이다.
- 레지스터는 MVP 개발 중 매일 갱신한다. 실제 사용자 파일럿을 승인하는 post-MVP 단계에서는 별도 위험 검토 후 주 1회 이상 갱신한다.

## 3. 상위 위험과 주간 검토

매일 검토할 상위 위험은 R01, R02, R03, R04, R06, R10, R13, R20이다. 1주차에는 계약·동의·재식별 통제를, 2주차에는 계산·이중 반영·철회 통합을, 3주차에는 AI·보안·성능을, 4주차에는 운영·롤백·접근성을 집중 검토한다.

MVP 위험을 닫으려면 예방 통제가 구현되고 계약 호환 어댑터·합성 데이터의 연결 테스트와 장애 주입이 통과해야 한다. 실제 비율·장기 관찰이 필요한 위험은 MVP에서 닫지 않고 `POST_MVP_VALIDATION_REQUIRED`로 인계한다. post-MVP 파일럿이 별도 승인되면 완전히 닫힌 관찰창의 선행 지표를 추가로 확인한다. 일정이 끝났다는 이유만으로 위험을 닫지 않는다. 잔여 점수 8 이상은 인수 문서에 명시하고 제품·엔지니어링·해당 전문 책임자가 수용해야 한다.

## 4. 즉시 보고 조건

다음은 30분 안에 제품·엔지니어링·개인정보·보안 책임자에게 보고한다.

- 비허용 개인정보 또는 원본 사용자 연결키 노출
- 공개 철회 후 24시간을 넘긴 재노출
- AI가 만든 잘못된 후보 ID·목표 수치의 실제 노출
- 투자 거래·금액·수익률에 연결된 성장·축하·경쟁 또는 경제 보상
- 중복 활성 목표, 진행률 원장 손상, 삭제 데이터의 복원 재등장

대응 중 핵심 기능을 유지할 수 있는 우선순위는 `AI 전량 폴백 → 공개 카드 조회 차단 → 새 목표 확정 차단`이다. 개인 기록 조회, 목표 일시정지·취소, 개인정보 철회·삭제 요청은 가능한 한 계속 제공한다.
